## 2. Mission

Decision **H1** says: *USMTF is the interface between systems. The atobrief YAML is
atobrief-internal. Anything that exchanges ATO data talks USMTF, and atobrief must provide a USMTF
export/API.* L3 parses USMTF only, and has no YAML adapter.

**Decision Desk A1 is still open:** does atobrief gain the missing ATO fields in this lane? The
recommended default, which **this briefing is written to**, is: **ship with what exists. Missing
fields are a later lane.** Appendix A describes the alternative in full, so that nothing has to be
re-researched if the human picks it.

Build the following:

1. **A two-layer pure exporter** in one file that runs in the browser and in Node:
   - **Renderer: `renderUsmtf(doc)`.** It turns an intermediate *ATO document model* (§5.3) into
     USMTF text. It supports **every set the research note profiles**:
     - `EXER/OPER`, `MSGID`, `AKNLDG`, `TIMEFRAM`, `GENTEXT`;
     - `TSKCNTRY`/`SVCTASK`/`TASKUNIT`;
     - `AMSNDAT` (12 fields), `MSNACFT` (11-field [PROFILE]), `AMSNLOC`, `GTGTLOC`;
     - `CONTROLA`, `ARINFO` (16-position [PROFILE]), `PKGCMD`, `9PKGDAT`;
     - `REFTSK`, `5REFUEL`, `7CONTROL`, `NARR`.

     This is independent of what atobrief can fill today. It is golden-tested against the research
     note's full fixture.
   - **Mapper: `atobriefToAtoDoc(pkg)`.** It turns an atobrief package into the document model,
     from **fields that exist today only** (§5.5). What atobrief lacks becomes `null`, and the
     renderer writes it as `-`. Each gap is reported as a warning.
   - `buildUsmtf(pkg) = renderUsmtf(atobriefToAtoDoc(pkg))`, with the warnings of both layers
     merged.
   - A later lane that adds YAML fields (A1) then touches **only the mapper**.
2. **An authenticated HTTP GET** that returns a briefing room's current package as `text/plain`
   USMTF, for L14 or crc-sync to fetch. There is also a stateless POST that converts YAML you send
   it.
3. **An in-app "USMTF" export**: a third format in the existing EXPORT dialog, with a preview,
   the warnings, COPY and DOWNLOAD.
4. **Tests.** atobrief has none today. Add a `node --test` suite with golden tests:
   - renderer against the research fixture;
   - mapper and exporter against a trimmed, anonymised copy of the squadron's real ATO
     `ojw1v5.yaml` (H16).
5. **ADR `0078`** and `docs/wip/L11.md`.

### Out of scope

- **No new YAML fields and no editor changes** (A1 default). Appendix A describes them for the
  later lane.
- **No crc-sync, crc-desktop or sourcedcs-web change.** Parsing is L3's job; fetching and binding
  are L14's.
- **No USMTF import into atobrief**, and no ACO export (`aco.*` maps to the separate ACO message,
  research §4). No `6ROUTE`. No SPINS, comms or weather content in the ATO (research §4.1).
- **No change to miztoyaml** (`tools/miztoyaml`), or to how SPINS C3 generates Mode 3 codes
  (random today: `atobrief/public/js/editor/editor-spins.js:35`–`:43`,
  `tools/miztoyaml/build_doc.py:193`–`:199`).
- **No `infra/docker-compose.yml`, `.env.example`, CLAUDE.md or README edit.** Put the lines they
  need in `docs/wip/L11.md` (§6.3).
- **Nothing theater-specific (H13).** No Syria, no ICAO list, no carrier id, no time offset baked
  into the exporter. Bases, carriers and coordinates come from the package only.
- **No coalition notion (H14).** The ATO is per package. `TSKCNTRY` is a per-document value that a
  package could override, never a global. Do not read `CRCSYNC_COALITION` or any global side.

### 5.2 Public API of `usmtf-ato.js`

```js
atobriefToAtoDoc(pkg, opts)  → { doc: AtoDoc|null, warnings: Warning[], errors: Warning[] }
renderUsmtf(doc)             → { text: string, warnings: Warning[] }
buildUsmtf(pkg, opts)        → { text: string|null, doc: AtoDoc|null, warnings, errors }
                                 // text === null iff errors.length > 0
packageToUsmtf(pkg, opts)    → string   // throws Error with .errors/.warnings on errors
_internal                    → { formatDtg, addMinutes, parseHhmm, placeTime, dmsToUsmtf,
                                 sanitiseField, iffToken, wrapLinearSet, wrapFreeText,
                                 layoutColumnar, callsignSeedable }

// opts: { defaults?: { unit, country, service, originator, messageKind } } — constants in the
//       module (§5.5); opts exist so tests and a future header block can override them.
// Warning = { code, severity: 'warning'|'info', missionNumber?, path?, message }
//   path like 'ato.missions[1].refuel[0].tanker_id'.
```

- **There is no `now` option.** Every DTG in an ATO is **in-game** UTC (research §1.4:
  `header.ato_date` is the in-game date, `ato.irl_*` is real-world time), and the wall clock has
  no in-game meaning.
  - `TIMEFRAM ASOF` is therefore left out. It is optional, and the mapper has no source for it.
  - The research note suggested an ASOF derived from `now` (§4, `ingame_start_time` row). ADR 0078
    records the departure and the reason: determinism, and in-game time only.
  - Freshness is provided by the HTTP `Last-Modified` header (§6.1).
- **Errors** (the export is refused):
  - `NOT_A_PACKAGE`: `pkg` is not an object, or has no `ato` object.
  - `NO_ATO_DATE`: there is no valid `YYYY-MM-DD` in `header.ato_date`. The mapper falls back to
    `ato.ato_day` first (the runtime copy, `app.js:384`). No DTG can be formed without a date.
- Everything else is a **warning**, and the export still goes ahead.
  - Zero missions gives a header-only message and warning `NO_MISSIONS`.

### 5.3 The ATO document model (the contract between mapper and renderer)

The model is plain JSON. It holds **semantic** values; the renderer does all formatting and
sanitising. Name fields after L3's parsed shapes (`L3.md` §5.4) where those exist, so that a
cross-lane test can later compare L3's parse of your text with your model.

```js
AtoDoc = {
  classification: 'UNCLAS',                 // first line, verbatim upper-cased
  messageKind: 'EXER' | 'OPER',
  operation: string,
  msgid: { originator: string, serial: string|null, month: 'JAN'..'DEC' },
  timeframe: { from: Dtg, to: Dtg, asof: Dtg|null },

### 5.4 Renderer: message layout, per-set shapes, formats

**Skeleton** (order is fixed):

```
<classification>

MSGID/ATO/<originator>/<serial|->/<MON>//         trailing '-' fields trimmed

- The renderer never emits `DECL` (§10 Q2).
- The text uses `\n` line endings and ends with exactly one `\n`, as the fixture does.

**Formats** (`_internal` helpers, each unit-tested):

| Thing | Rule | Example |
|---|---|---|
| `DDHHMMZMONYYYY` | TIMEFRAM only | `040220ZJUL2026` |
| `DDHHMMZMON` | AMSNDAT f10/f12, AMSNLOC f1/f2, `TOT:`, `NET:`, `NDAR:` (research §1.4) | `040300ZJUL` |
| `DDHHMMZ` | `NLT:`, `ARCT:`, 5REFUEL ARCT, 7CONTROL TOSTA, codeword times | `040345Z` |
| IFF token | Mode digit + code. Mode 1 is 2 digits (the first `0-7`, the second `0-3`), giving `1dd`. Modes 2/3 are 4 octal digits, giving `2dddd`/`3dddd`. `null` gives `-`. A malformed code gives `-` plus warning `IFF_MALFORMED`. Mode 3 `7500`/`7600`/`7700` is emitted anyway, with warning `IFF_RESERVED` (L3 keeps and warns too) | modeThree `4001` → `34001` |
| Frequency | An integer gets `.0`. Otherwise the given decimals are kept with trailing zeros dropped, keeping at least 1 decimal. Not finite gives `-` plus warning `BAD_FREQUENCY` | `261.500` → `261.5`; `251` → `251.0` |
| Altitude | `Math.round(ft / 100)`, no padding | `25000` → `250` |
| Offload | `toFixed(1)` | `12` → `12.0` |
| Coordinates | `{lat, lon}` in decimal degrees becomes `DDMMSS`+`N/S`+`DDDMMSS`+`E/W`. Round to whole seconds, carrying 60 s into minutes and 60 min into degrees | `33.5025, 36.269717` → `333009N0361611E` |
| Elevation | `<integer>FT` | `120FT` |

**Character set.** `sanitiseField(s)` does the following:
- It upper-cases the value.
- It replaces `/` with a space.
- It replaces every character outside `A–Z 0–9 space . , - ( ) : +` (research §1.2) with a space.
  That includes `_`, `°`, quotes and newlines.
- It collapses runs of spaces, then trims.
- If anything other than case, `_` or whitespace changed, it adds warning `CHARSET_REPLACED`, with
  the path if known.
- An empty result becomes `-`.

Never emit `//` inside a set, a field with a leading space, or `/` inside free text.

**Line layout.**
- **Linear sets.** Build the logical string `SETID/f1/…/fn//`, then wrap it.
  - Break **only directly after a `/`**, and never between the two slashes of `//`.
  - Indent continuation lines by **5 spaces**.
  - Wrap greedily: fit as many whole `field/` tokens on a line as keep it at **≤ 69 characters**
    (research §1.2).
  - A token that does not fit even on a fresh continuation line goes on its own overlong line,
    with warning `LINE_TOO_LONG`.
  - L3 un-wraps by deleting each newline together with the whitespace that follows it (research
    §1.2, L3 §5.3 rule 5).
- **Free text** (`NARR`, the text part of `GENTEXT`).
  - Break **after a space, which stays at the end of the line**, with continuation lines indented
    by 5 spaces. Deleting `\n` plus the leading whitespace then gives the text back exactly
    (research §3, the GENTEXT bullet).
- **Columnar sets.**
  - The set name stands alone on its line, with no trailing `/`.
  - Next comes the header row, then one row per data line. Each row is `/`-prefixed.
  - Pad every column **except the last** to (the longest of its header and values) + 1. The last
    column is not padded.
  - The last row ends with `//`.
  - Rows are never wrapped. A row longer than 69 characters gets warning `LINE_TOO_LONG` and is
    emitted anyway.
- **The research fixture cannot be reproduced byte for byte, and that is expected.** It was laid
  out by hand.
  - Its `AMSNDAT 1203S` and `1801W` wrap before the 69-character greedy point. This was checked:
    no single line limit reproduces every one of its wrap points.
  - Its `NO` and `OFLD` columns carry one space less than the uniform rule.
  - So the golden tests compare **semantically** against the fixture, and **byte-exactly** against
    your own committed output (§7, step 5).

### 5.5 Mapper: atobrief (fields that exist today) → AtoDoc

**How input is read.**
- `registry.tankers` may be a **list or a dict**. The tanker key is `id || callsign`
  (`app.js:364`). A `refuel[].tanker_id` also matches on `callsign`.
- Skip `_`-prefixed keys. Ignore `ato.targets`.
- Prefer `header.*` over copies on `ato.*`.
- A legacy singular `target` counts as `targets: [target]`.
- `null` counts as absent everywhere.
- **Times.** Accept `'0300Z'`, `'0300'`, `'0300L'`, or a number (`300` means `0300`; an unquoted
  `0240` loads as the number 240).
  - `L` is converted with `ato.local_offset_hours`. This should not occur, because the editor
    always writes Z.
  - Anything else gives `null` plus warning `BAD_TIME`, with the path.
- **Day rollover.** A time is placed on the day of TIMEFRAM FROM. If it is **earlier than FROM's
  HHMM**, it goes on the next day, and month and year roll with it. For example, with FROM
  `040220Z`, `0130Z` becomes `050130Z`.
- **Coordinates.** Parse DMS and DM the way `app.js:83` does: copy the regex into the module and
  say so in a comment.
  - Accept 1–3-digit degrees, since ojw1v5 has `E36°…`.
  - Unparseable coordinates give `null` plus warning `BAD_COORDS`.

## 6. HTTP endpoint and in-app export

### 6.1 Routes (`atobrief/usmtf-api.js`)

`mountUsmtfRoutes(app, { sessions, serviceToken })` mounts two routes.

**`GET /api/rooms/:id/ato.usmtf`** returns the room's current package as USMTF.

1. `requireUsmtfReader` (below) runs first. Then a dedicated limiter, `rateLimit({ windowMs:
   60_000, max: 60, standardHeaders: true, legacyHeaders: false })`.
2. Validate `:id`: it must be non-empty and at most 128 characters, otherwise `400`.
3. Look up the room.
   - No room → `404 {error:'No such room'}`.
   - `packageYaml === null` → `404 {error:'Room has no package'}`.
4. Parse with `require('js-yaml').load(...)`, inside try/catch.
   - A parse error → `422 {error:'YAML parse error', detail}`.
   - Exporter errors → `422 {errors, warnings}`.
5. On success, return `200` with these headers:
   - `Content-Type: text/plain; charset=utf-8`
   - `Cache-Control: no-store`
   - `X-Usmtf-Warnings: <count>`
   - `ETag: "<sha1 of text>"`
   - `Last-Modified` from `session.packageUpdatedAt`, left out when unknown
   - `Content-Disposition: inline; filename="<operation>_<ato_date>.usmtf.txt"`, with the file
     name sanitised to `[A-Za-z0-9._-]`

   The body is the text.
6. `?report=1` returns `application/json {text, warnings}` instead.
7. `If-None-Match` matching the ETag returns `304`.

**`POST /api/usmtf`** converts a package in one call, for packages that are not in a room (a CLI,
CI, tests).
- Use a route-scoped `express.text({ type: ['text/yaml','application/yaml','application/x-yaml',
  'text/plain'], limit: '1mb' })`. The global `express.json` at `server.js:57` does not apply.
- It uses the same auth, limiter and responses.

**`requireUsmtfReader(serviceToken)`** accepts `Authorization: Bearer <x>` when either of these
holds:
1. `x` equals `serviceToken`, compared in constant time.
   - Copy `checkReleaseUploadToken` from `sourcedcs-web/releases.js:39`–`:45`, and say where it
     came from.
   - An unset or empty `serviceToken` disables this path; it never matches an empty bearer.
   - This is the path crc-sync (L14) will use. It has no interactive Casdoor session, the same
     situation as `sourcedcs-web/auth.js:38`–`:56`.
2. `x` decodes as a JWT with a non-empty `roles` array and an unexpired `exp`.
   - Use an unsigned decode, as `crc-sync/src/auth.js:70`–`:77` does.
   - This is the same bar as atobrief's own page gate (`index.html:245`–`:275`).
   - The decode is forgeable. Say so in a comment and in the ADR. Presentees already receive the
     whole YAML with no auth at all (`server.js:245`–`:251`), so this gate adds protection and
     takes none away (§10 Q5).

Anything else returns `401 {error:'Authentication required'}`.

`server.js`: `const USMTF_SERVICE_TOKEN = process.env.ATOBRIEF_USMTF_TOKEN || ''`, read once, next
to `:44`–`:46` (P5).

- **T1. The planning docs:** read `decisions.md` by absolute path, because mid-wave rulings land
  only in the main checkout. Never create or edit `docs/parallel/` in your branch.
- **T2. Never export `_vul_start`, `_vul_end` or `_marshal_time`.** They are IP/EP/marshal times
  (`app.js:525`–`:547`): not the vul window and not a check-in time. Filtering `_` keys is not
  enough on its own; do not re-derive them either. If L3 gets them, it would seed a wrong M6.
- **T3. The runtime shape is the real input.** ojw1v5 is editor-saved: `ato` comes first, tankers
  are a dict, `ato.targets` is injected, and header values are copied into sections. Test both
  shapes (step 5, test 5).
- **T4. The browser loads plain scripts.** `usmtf-ato.js` must not use `require`, `import`,
  `Buffer` or `crypto` at the top level. Its only global is `UsmtfAto`, and every helper stays
  inside the closure. `app.js` already defines `el`, `html`, `toMins`, `parseCoord` and more.
- **T5. Orbit altitude is not where the doc says.** ojw1v5 keeps it in the steerpoint's
  `altitude_ft`, not in `orbit.alt_ft` (`yaml-format.md:602`). Check both.
- **T6. Numbers where strings are meant.** An unquoted `0240` loads as `240`, and an unquoted Mode
  3 `0011` loads as `11`. Coerce with `String()` and left-pad. Warn with `IFF_NOT_STRING` when a
  code arrives as a number.
- **T7. The mission-number form.** The editor forces `MSN` (`editor-missions.js:337`–`:338`), while
  SPINS and miztoyaml strip it (`editor-spins.js:46`–`:48`, `build_doc.py:238`). The export strips
  it, and the C3 match compares **stripped to stripped**.
- **T8. Day rollover.** An ATO that starts at `2300Z` puts a `0100Z` mission on the next day
  (§5.5). ojw1v5 starts at `0220`, so a `0200` time would roll over. Test the month and year edges.
- **T9. `+` in loadout codes, and long callsigns**, are known open points (research §1.2, §2.3).
  Emit `+`, and add an info for seedability. Neither is an error.
- **T10. Do not "fix" the research fixture.** Its deliberate edge cases (research `:558`–`:566`),
  such as `NLT:` in `DDHHMMZ` form next to `NET:` in `DDHHMMZMON` form, are what your per-field
  DTG table reproduces.
- **T11. The research fixture is not reproducible byte for byte** (§5.4). Do not tune the wrap rule
  to match it. The semantic test is the contract.
- **T12. Node 20 in Docker, Node 22 locally.** Tests do not run in the image
  (`.github/workflows/atobrief-docker.yml` only builds it), but runtime code must work on Node 20.
  `fetch` appears only in tests. The `test/*.test.js` glob is expanded by the shell, as in
  `sourcedcs-web`.
- **T13. `express.json` is global and limited to 50 kb** (`server.js:57`). It ignores `text/yaml`,
  so the POST route needs its own `express.text`. Do not raise the global limit.
- **T14. Room YAML may be large or hostile.** js-yaml 4's `load` is safe by default (there is no
  `!!js/function`). Wrap it in try/catch. The 1 MB POST limit and the limiter bound the cost.
- **T15. Do not touch `infra/`, `.env.example`, CLAUDE.md or any README** (P3). Put what they need

- **T16. Nothing theater- or side-specific** (H13, H14). The carrier in ojw1v5 is labelled `CVN-75`
  and the squadron's real carrier is CVN-72 `UNION`, but that is package data. The exporter copies

## Appendix A: the A1 alternative (not in scope unless A1 is answered "add now")

This appendix keeps the design ready, so that a later lane, or this one if the human answers A1
"now", does not have to re-research it. In that case only the **mapper** and the **editor** change.
The renderer is already complete.

**Optional YAML fields**, flat on the object they describe, except for a `header.usmtf` block:

| Path | Type | Fills |
|---|---|---|
| `header.usmtf.{message_kind, originator, serial, asof, country, service, default_unit}` | strings; `asof` is `'YYYY-MM-DD HHMMZ'` in-game | `EXER`/`OPER`, `MSGID`, `ASOF`, `TSKCNTRY`/`SVCTASK`, default unit |
| `registry.units.<unit>.{base, remarks}` | ICAO, text | `TASKUNIT ICAO:`, `GENTEXT/UNIT REMARKS` |
| `missions[].package_id`, `package_commander` | string, bool | AMSNDAT f4/f5, `PKGCMD`, `9PKGDAT` |
| `missions[].iff.{mode1,mode2,mode3}` | octal strings | MSNACFT IFF. `mode3` wins over SPINS C3, with `IFF_SPINS_MISMATCH` when they differ |
| `missions[].datalink.{l16_callsign,tacan,ju}` | strings | MSNACFT f6–f8 |
| `missions[].alert_status`, `priority`, `narrative` | string, int, text | AMSNDAT f8, AMSNLOC f5, `NARR` |
