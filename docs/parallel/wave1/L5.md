## 1. Mission

WP8's deliverables are "audit log; traffic count (§11.4); the §11.5 metric set with a dashboard;
staleness detection (§10.4); soak test". This lane is the **server half of three of them**:

1. **The §11.5 metric set, collected server-side** — every one of the seven rows has a collection
   path in crc-sync, is aggregated into UTC-hour buckets that survive a restart, and is readable
   through one HTTP endpoint and one WS request. The three that only a client can observe (search
   invocations, time-to-find, inputs per gesture) get a **defined inbound message** and server-side
   aggregation; L15 builds the client that sends it. Staleness (§10.4) gets a **hook** that L19
   calls; until then it reports `NOT_INSTRUMENTED`, never `0`.
2. **The §11.4 traffic count** from `DROPPED` Strips — categories local, transient, formation, SUA
   traversal, alert scramble; hourly buckets; by aircraft type — and a **reconciliation against the
   Mutation log** (WP8 acceptance bullet 3).
3. **§11.3 Mutation-log retention as configuration**, default 30 days, stated as a SOURCE policy
   choice, with a rotation that never rewrites an entry.

## 4. The shape of the solution, in one paragraph

Three new modules and one config file, **zero edits to the stores or the wire handler**.
`mutation-log.js` gains retention/rotation and an `onRecord(listener)`; `traffic-count.js` listens
to the log, freezes a count record at each drop, voids it on Undo, and can replay the log to prove it
agrees; `metrics.js` wraps the facade's `handleMessage`/`onDisconnect` (a tap that sees every
message, its session and its ack) to count rejections, transfers and flag gestures, accepts
client-reported measurements and serves reads as two new WS message types, samples Position manning
and correlation once a minute, and keeps UTC-hour buckets in its own atomically written state file.
server.js gets one appended block that builds it all and adds two GET routes.

## 5. Design

### 5.1 Configuration — `crc-sync/config/efsp-instrumentation.json` (new, tracked) + `src/efsp/instrumentation-config.js` (new)

```json
{
  "_note": "SOURCE policy choices, not doctrine (guide §11.3, §11.4). Read once at startup; edit and restart.",
  "mutationLog":  { "retentionDays": 30 },
  "metrics":      { "retentionDays": 30 },
  "trafficCount": {
    "retentionDays": 400,
    "homeAirports": { "INCIRLIK": ["LTAG"] }
  }
}
```

- Loaded **once at module load** via `readPath('efsp-instrumentation.json', process.env.CRCSYNC_EFSP_INSTRUMENTATION_CONFIG_PATH)`
  (state/ override wins, else the shipped default), validated, deep-frozen. **Never written by code**
  (P5). Invalid values warn and fall back to the defaults above, per field — a typo must not stop
  the server or silently mean "keep forever".
- `retentionDays` must be an integer ≥ 1. `homeAirports` values are uppercased and trimmed. A
  Facility absent from `homeAirports` has none, which makes its locality `UNKNOWN` (§5.3) rather
  than guessed.
- Exports `getInstrumentationConfig()` and the defaults. Also accept a plain object in each consumer's
  constructor (`{ retentionDays }` etc.) so tests never depend on the file.
- Why a new file and not `facility-config.js`: that file is serialised L1 → L13 → L17 (plan §2), and
  this is policy, not a Facility's shape. Open question Q5.

### 5.2 §11.5 — the seven metrics

Every metric in the report carries `status`: `COLLECTING` (a source is wired and data may be zero),
`NO_DATA` (wired, nothing in the window), or `NOT_INSTRUMENTED` (no source has ever reported). **A
missing source must never render as a healthy zero** — the same discipline as the correlation rate's
"null, never 1.0" (`correlation-reconciler.js:359–371`).

All buckets are keyed by **UTC hour**, `YYYY-MM-DDTHH:00Z` (guide §11.2: all times UTC), computed
from an injected `now()`.

| # | Metric (§11.5) | Source | Hook | Aggregation | Target (report as data) |
|---|---|---|---|---|---|
| 1 | Search invocations per Position per hour | **client** | `efsp-metrics-report` event `SEARCH` | per hour per Position: count. Denominator: **manned minutes** per Position per hour, sampled by the 60 s tick from each `positionStore.getAll()` (a Position with a `primary`). Rate = searches ÷ (mannedMinutes ÷ 60); `null` when unmanned | `TRENDING_DOWN` (show hourly series) |
| 2 | Time-to-find (Strip selection after Bay entry) | **client** | event `TIME_TO_FIND` `{ bayId, latencyMs }` | per hour per Position: raw samples, capped at 500 per bucket (drop newest beyond cap, count `dropped`); exact p50/p95/max computed on read | `p95Ms < 3000` → `pass: true/false/null` |
| 3 | Inputs per paper-gesture | **client** | event `GESTURE` `{ gesture, inputs }`, gesture ∈ `OFFSET FLIP HIGHLIGHT ATTENTION` | per hour per gesture: `count, inputsSum, inputsMax, overCeiling` (inputs > 1). Server cross-check: successful `SetFlag` Mutations per flag (`offset`→OFFSET, `flipped`→FLIP, `highlight`→HIGHLIGHT, `attention`→ATTENTION; `removeIndicator` ignored) from the tap | `= 1` |
| 4 | Strip↔track correlation rate | server | `correlationStats()` getter → `CorrelationReconciler.getStats()` | every 60 s tick, when `rate !== null`: `matchedSum += rate × eligible`, `eligibleSum += eligible`, `samples++`. Hourly rate = matchedSum ÷ eligibleSum (`null` when 0). Also report the live `getStats()` object verbatim | `≥ 0.95` |
| 5 | Rejected Mutations per session, by reason | server | the tap: any `msg.type` ending in `-mutation` whose `ack.ok === false` | per hour: `total, byReason, byType, byOp, byPosition`; plus `mutations` (all attempts) for a denominator; plus per-WS-session records (below) | `TRENDING_DOWN` |
| 6 | Staleness detections (§10.4) | server, **L19** | `metrics.declareSource('staleness')` at wiring + `metrics.recordStaleness(o)` per occurrence | per hour: `total, byPosition, byState` | `TRENDING_DOWN` |
| 7 | Transfer failures and causes | server | the tap (below) | per hour: `attempts, succeeded, failed, routedToCovering, byCause, byKind`; `failureRate = failed ÷ attempts` (`null` when 0) | `failureRate ≤ 0.005` (§11.1: success ≥ 99.5%) |

Plus two non-§11.5 rows the plan names: **obligation compliance** (`obligationStats()` getter →
`getComplianceStats()`, reported live and verbatim, not persisted — L7 owns its meaning) and
**system reassignments** (log entries with `op === 'SystemReassign'`, per hour).

**The tap — what counts as what.** `instrumentEfsp()` (§5.4) wraps `efsp.handleMessage`:

- **Dedupe by `clientMutationId`.** A reconnecting client replays its queue (§5.6 of the guide);
  board-store returns the cached result (`board-store.js:239–241`). Keep a bounded `Set` (cap 5000,
  evict oldest — `APPLIED_MUTATIONS_CAP`'s shape) and count each id once. A message with no
  `clientMutationId` is counted every time.
- **Mutation attempts / rejections**: type matched by `/-mutation$/` — an **exclusion-by-shape rule,
  not an inclusion list of types** (ADR `0041`'s lesson), so L1/L14/L17's new dispatch paths are
  counted without anyone remembering to. Reason = `ack.reason || 'UNKNOWN'`; op = `msg.op && msg.op.kind`.
- **Transfer attempts**: `efsp-mutation` with `op.kind === 'TransferStrip'` (kind `TRANSFER`), **or**
  `op.kind === 'InvokeNla'` where, **before** delegating, the Strip exists, its
  `ownerPositionId === msg.actingPositionId`, and `boardStore.nlaStatusFor(strip)` returns an object
  with `transferTo` (kind `NLA_TRANSFER`). The owner check matters: a second tap arriving after the
  first transfer committed would otherwise be scored against the receiver's NLA (trap T4).
  Outcome = `ack.ok`; cause = `ack.reason`; `ack.routedTo` → `routedToCovering++`. `STALE_REV` and
  `NOT_HOLDING_POSITION` **count as failures** — the guide says the real failure residue clusters
  around "restarts and message latency" (§4.5), which is exactly those. Cross-Facility `HANDOFF`
  (a coordination primitive) is **not** a transfer here: a REJECT is a controller's decision, not a
  failure. Q9.
- **Gestures (server side)**: `efsp-mutation`, `op.kind === 'SetFlag'`, `ack.ok` → per-flag count.
- **Per-session**: a `WeakMap(session → { sessionId: uuid, controllerId, startedAt, endedAt, mutations,
  rejected, byReason, transfers: {attempts, failed} })`, created on the first message seen. Wrap
  `efsp.onDisconnect` the same way to stamp `endedAt` and move it to a ring of the last 50 ended
  sessions. In-memory only; a WS session cannot outlive the process anyway.
- **The tap never throws and never changes the result.** Wrap all tap work in try/catch → `console.warn`;
  always return exactly what the wrapped function returned.
- **Strip-op refusals go into the Mutation log** (default of Q2). §11.3 says *every* Mutation is
  recorded; the other three stores already log refusals (ADR `0040` found airspace refusals invisible
  and fixed exactly this); board-store does not. From the tap, for every refused `efsp-mutation`
  (after dedupe), and for `NOT_HOLDING_POSITION` on any `-mutation` type (no store ever sees those):
  `mutationLog.record({ clientMutationId, op, stripId|airspaceId|fdrId|marsaId (from the msg),
  facilityId, actingPositionId, actorId: session.controllerId, at, ok: false, reason, detail,
  source: 'wire' })`. Airspace/correlation/MARSA refusals that reached their store are **not**
  logged again. Every log consumer you write filters `ok === false` out (T7).

**Client-reported events** (metrics 1–3) arrive as `efsp-metrics-report` (§5.6), intercepted by the
tap *before* delegating (efsp-ws returns `null` for unknown types, so nothing else sees them):

- The reporting controller must currently hold `positionId` at `facilityId` as **Primary or
  Observer** (`positionStore.primaryOf(p) === controllerId || observersOf(p).includes(controllerId)`,
  `position-store.js:44–52`) — the ADR `0029` binding: a client claim is checked at the wire.
  Otherwise ack `ok:false, reason:'NOT_HOLDING_POSITION'`.
- ≤ 100 events per report; `latencyMs` integer 0…600000; `inputs` integer 1…50; `gesture` in the
  enum; `at` within ±10 minutes of server `now()` else the event is rejected (bucket by `at`
  otherwise). Invalid events are rejected individually and listed in the ack; valid ones in the same
  report are kept.
- Dedupe by `reportId` (bounded Set, 1000). No search text is ever sent or stored.
- The first valid event of any kind stamps `sources.client = at` (persisted); from then on metrics 1–3
  are `COLLECTING` rather than `NOT_INSTRUMENTED`.


### 5.3 §11.4 — the traffic count (`src/efsp/traffic-count.js`)

**Unit.** One **count record per countable `DROPPED` ATC Strip at a Facility.** Report both
`flights` (records) and `aircraft` (Σ `flightSize`) everywhere, with `flights` as the headline (Q3).
Each Facility counts its own traffic — a DEPARTURE handed from INCIRLIK to CENTER is counted once at
each, which is what two real facilities would each report. Within one Facility, one flight's
DEPARTURE converted in place to an ARRIVAL is **one** Strip, so one record (`legs: 2`, Q3).

**Event.** A log entry is a **drop** when `entry.ok !== false && entry.after && entry.after.state ===
'DROPPED' && (!entry.before || entry.before.state !== 'DROPPED')`. It is an **undo of a drop** when
`entry.op === 'Undo' && entry.before && entry.before.state === 'DROPPED' && entry.after.state !==
'DROPPED'`. Nothing else changes the count. These two predicates are pure, exported, and used by both
the live listener and the reconciliation — one definition, two callers.

**Countability — a pure function of the `entry.before`/`after` Strip records only** (so the
reconciliation can decide it from the log alone). A drop that is not countable still produces a
record, with `counted: false` and an `excludedReason`, so every drop in the log has exactly one
record and the reconciliation is total:

| Case | Rule | `excludedReason` |
|---|---|---|
| MISSION role | never — it shares its `fdrId` with the ATC Strip TOFI linked it to, so counting it double-counts the aircraft (and TACTICAL runs no field) | `MISSION_LINE` |
| Rejected coordination replica | `after.coordination && after.coordination.state === 'REJECTED' && after.coordination.mintedForCoordination` (the flight never became this Facility's traffic; `board-store.js:1127–1132`) | `REJECTED_REPLICA` |
| DEPARTURE | counted iff `before.state ∈ { DEPARTED, HANDED_OFF }` | `NEVER_DEPARTED` |
| ARRIVAL | counted iff `before.state ∈ { LANDED, TAXI_IN }` | `NEVER_LANDED` |
| OVERFLIGHT | counted (`TRANSITING` is its only live state) | — |
| any other Role | **not counted, and a test fails** (below) | `UNCLASSIFIED_ROLE` |

The per-Role table is data (`COUNTABLE_PRE_DROP_STATES = { DEPARTURE: [...], ARRIVAL: [...],
OVERFLIGHT: ['TRANSITING'], MISSION: [] }`). **A test holds every Role in `nla.js`'s
`STATES_BY_ROLE` to having an entry**, so L17's CARRIER roles (or any new Role) force a decision
instead of silently vanishing from the count — `correlation-reconciler.js:44–52`'s exclusion-list
argument, applied here. Q4 has the thresholds.

**Categories.** Frozen at the moment of the drop, from the log entry plus the FDR as it is **right
then** (`fdrStore.getFdr(after.fdrId)` — the FDR outlives the Strip, T5). The Facility is found by
asking each `boardStoreFor(f).getStrip(stripId)` (the entry has no `facilityId`, T6).

- **Locality** — exactly one of `LOCAL | TRANSIENT | UNKNOWN`, with a `localityBasis`:
  - OVERFLIGHT → `TRANSIENT` (`OVERFLIGHT`): it never touches the field (`block-map.js:276–286`).
  - ARRIVAL with `previousLeg` → `LOCAL` (`CONVERTED_ARRIVAL`): it departed this Facility and came back.
  - Facility has no configured `homeAirports` → `UNKNOWN` (`NO_HOME_AIRPORT_CONFIGURED`). This is
    CENTER and TACTICAL out of the box, and it is honest: "local" means nothing to a centre.
  - DEPARTURE: both `filed.departureAirport` and `filed.destinationAirport` non-empty → `LOCAL` iff
    both are home airports, else `TRANSIENT` (`AIRPORTS`). Either empty → `UNKNOWN` (`NO_AIRPORT_DATA`).
  - ARRIVAL: `filed.originAirport` non-empty → `LOCAL` iff it is a home airport, else `TRANSIENT`;
    empty → `UNKNOWN`.
  - Compare uppercased and trimmed. Do **not** use `identity.homeStation` — it is the unit's home, not
    the field's.
  - `[SOURCE-DEFINED]`: this is "a sortie that starts and ends here is local". Real tower counts also
    call pattern work and practice approaches local; the EFSP has no data for those. Say so in the ADR.
- **Formation** — `flightSize > 1` at the drop. Record `flightSize`.
- **SUA traversal** — the airspace ids this Strip was approved into during its life. Kept as an
  in-memory latch `Map(stripId → Set(airspaceId))` fed by every log entry with `op ===
  'ApproveAirspaceEntry'` (read `entry.after.airspaceEntry.airspaceId`). Rebuilt at boot by scanning
  the retained log for Strips still live (they are the only ones whose latch can matter). Because it
  comes from the log, it **reconciles** (§5.3 reconciliation checks it). `suaTraversal` = the sorted
  list, category true when non-empty.
- **Alert scramble** — `fdr.military.alertStatus === 'SCRAMBLE'` at the drop, **or** seen at any
  logged Mutation of this Strip while it was live (latch: on every log entry with a `stripId`, read the
  entry's FDR and latch `SCRAMBLE`). There is no history of `alertStatus` anywhere, and L13 has not
  decided whether it resets on airborne — the latch makes the category survive that. It does **not**
  reconcile from the log (the FDR is not in it). Q11: L13 must write `alertStatus` through a logged
  Strip Mutation, or call `trafficCount.noteFdr(fdrId)` from wherever it writes it.
- **Aircraft type** — `identity.aircraftType` trimmed and uppercased; `''` → `UNKNOWN`.

**The count record** (one JSONL line; the file is `state/efsp-traffic-count.jsonl`):

```json
{ "type": "COUNT", "countId": "<stripId>:<clientMutationId|at>", "stripId": "...", "fdrId": "...",
  "facilityId": "INCIRLIK", "role": "DEPARTURE", "callsign": "VIPER11",
  "droppedAt": 1790000000000, "hourUtc": "2026-09-29T13:00Z",
  "dropOp": "InvokeNla", "dropClientMutationId": "...", "actingPositionId": "TWR", "actorId": "...",
  "counted": true, "excludedReason": null,
  "aircraftType": "F-16C", "flightSize": 4, "legs": 1,
  "locality": "LOCAL", "localityBasis": "AIRPORTS",
  "formation": true, "suaTraversal": ["R-7201"], "alertScramble": false,
  "backfilled": false }
```

and a void on Undo: `{ "type": "VOID", "countId": "...", "at": ..., "clientMutationId": "...", "actorId": "..." }`.
Voids are appended, never an in-place edit; a later re-drop of the same Strip is a new `COUNT` with a
new `countId`. `callsign` is the FDR's controller-entered callsign — never a DCS track callsign (ADR
`0059`: the wire carries no DCS truth).

**Hour bucket** = UTC hour of `droppedAt` (Q6 — the drop is when the Strip's life ended, not
necessarily the takeoff/landing minute; `[SOURCE-DEFINED]`).

**Persistence.** Append-only JSONL, one `appendFileSync` per drop/void (drops are tens per hour).
At construction: read the file, apply voids, drop records older than `trafficCount.retentionDays`
by rewriting to a sibling `.tmp` and renaming (atomic — `index.js:431–437`'s pattern), **only at
boot**. Env override `CRCSYNC_EFSP_TRAFFIC_COUNT_PATH`; default `writePath('efsp-traffic-count.jsonl')`.
It is **not** part of `efsp-board.json` (§5.5).

**Reconciliation — WP8 acceptance bullet 3.** Pure, exported:

```js
reconcileTrafficCount(logEntries, countEntries, { from, to }) →
  { ok, window: { from, to }, expected, actual,
    missing: [{ stripId, droppedAt, clientMutationId }],   // a drop in the log, no live record
    extra:   [{ countId, stripId, droppedAt }],             // a live record, no drop in the log
    mismatched: [{ countId, field, log, count }] }         // same drop, disagreeing on a log-derivable field
```

Replay the log in order: per `stripId`, a drop opens a pending record (`countable` and
`excludedReason` from the pure rule, SUA from `ApproveAirspaceEntry` entries seen before it), an undo
of a drop voids the last one. Compare the surviving set, keyed by `countId`, against non-voided
count records whose `droppedAt ∈ [from, to)`. Log-derivable fields that must agree: `stripId`,
`droppedAt` (the entry's `at`), `hourUtc`, `role`, `counted`, `excludedReason`, `suaTraversal`,
`dropOp`. The FDR-derived fields (locality, formation, type, scramble) are checked by unit tests of
the classifier, not by the reconciliation — say this in the ADR rather than implying more.

`from` defaults to the oldest retained log entry, so the reconciliation only ever compares the
window **both** stores still hold (the count outlives the log: 400 vs 30 days).

**Boot reconciliation.** After loading, `TrafficCount` runs `reconcileTrafficCount` over the retained
log. `missing` entries are **backfilled** — classified from the log entry and the FDR as it is now,
written with `backfilled: true` — and a warn names how many. `extra` and `mismatched` are warned and
kept (never delete a record because the log lost something). The last result is kept and served
(§5.6) so the dashboard can show "reconciles: yes/no".

### 5.4 Mutation-log retention (`mutation-log.js`, shared-with-no-one but listed in plan §4)

Constructor becomes `constructor(filePath, opts = {})` with `opts.retentionDays` (default from
§5.1's config, 30) and `opts.now` (default `Date.now`) — backward compatible with every existing
`new MutationLog(path)` and with `index.js:63`'s `new MutationLog()`, so **index.js needs no edit**.

**Rotation by day segment, never by rewrite.** The live file stays `efsp-mutations.jsonl` (every
existing test and `MUTATION_LOG_PATH` keep working). Before each append:

1. `activeDay` = UTC day of the live file's **mtime** (cached after the first stat; the file's last
   write is its newest entry).
2. If `activeDay !== today(now())` and the file is non-empty: rename it to the sibling
   `efsp-mutations.YYYY-MM-DD.jsonl` named by **activeDay** (the day of its newest entry). If that
   name exists, add `.1`, `.2`… . Then prune.
3. Append as today.

**Prune**: delete sibling segments `<base>.<day>[.<n>].jsonl` whose `day < today − retentionDays`.
Also run once in the constructor, so an idle server still prunes at boot. Match the exact base name
of *this* log's path — never glob a directory for `*.jsonl` (tests share tmp dirs; T10).

Because a segment is named by its **newest** entry, a legacy live file spanning many days (the dev
box's, T9) is kept until its newest entry expires — rotation never deletes anything younger than
the retention. Nothing is ever rewritten: §11.3's "append-only" holds, and retention is whole-segment
deletion, which is the policy the guide asks to be configurable.

**Reading.** `readAll()` reads the retained segments in day order, then the live file (same return
shape). Add `readSince(ms)` that skips segments whose day is before `ms`'s day. Both stay off the hot
path — boot reconciliation and tests only.

**Listener.** `onRecord(fn)` registers a callback called **synchronously after a successful append**
with the entry. A listener that throws is caught and warned; it never breaks `record()` and never
stops the next listener. A failed append (already warned by `:37`) does **not** notify — so the
count is always a subset of the log and a disk failure shows up as `missing` in reconciliation, not
as a phantom record.

- pruning only touches files with this log's base name (put an unrelated `other.2020-01-01.jsonl`

- constructor prunes at boot;

## 8. Traps

- **T1 — board-store never logs a refusal**, and most refusals return before `_recordAudit` is even
  reached (`board-store.js:291–315`). Rejection counts cannot come from the log as it stands; they come
  from the tap, which then writes them there.
- **T2 — idempotent replay.** A reconnect replays Mutations with the same `clientMutationId`; the
  store answers from cache and logs nothing. Without dedupe every reconnect doubles the rejection
  and transfer counts.
- **T3 — the 400 ms double-tap guard** (`board-store.js:1276–1283`) answers a second press with
  `ok:true` and no change. In scenario tests use the harness's `advance()`, never raw `InvokeNla`
  twice in a row.
- **T4 — a transfer NLA pressed twice.** After the first commits, the Strip belongs to the receiver;
  `nlaStatusFor` then describes *their* next step. Only score an NLA as a transfer when the acting
  Position owns the Strip at the time of the press.
- **T5 — the FDR outlives the Strip and keeps changing.** A DEPARTURE dropped at HANDED_OFF shares
  its FDR with CENTER's live replica and maybe a MISSION Strip. Freeze categories at the drop; never
  re-derive a finished record from today's FDR (backfill is the one exception and says so).
- **T6 — log entries have no `facilityId`** and no FDR. Look the Facility up on the Boards (DROPPED
  Strips are never deleted, so this always works for a Strip that exists).
- **T7 — the log now holds `ok:false` entries** (yours, and already the airspace/correlation/MARSA
  ones). Every consumer you write filters them: a refused `DropStrip` with a `strip` in its payload
  must not look like a drop. The drop predicate requires `entry.ok !== false`.
- **T8 — `airspaceEntry` is cleared on exit.** At drop time it is usually null. SUA comes from the
  `ApproveAirspaceEntry` history, not from the final Strip.
- **T9 — the legacy live log spans many days.** Name and prune segments by their **newest** entry
  (mtime), or the first rotation on a real server deletes last week's audit trail.
- **T10 — tests share tmp roots.** Prune by exact base name, never `*.jsonl`.
- **T11 — scenario boards are durable and shared per file** (`docs/efsp-briefing.md:174–177`,
  `:550–551`). Absolute counts belong to the whole file. Give your scenario file its own paths and
  compute expectations from what *this file* did.
- **T12 — TDZ in server.js.** `correlationReconciler` and `obligationMonitor` are `const`s declared
  after your block. Closures over them are fine; calling them during construction throws
  `ReferenceError`. Nothing may run the getters until the first tick/request.
- **T13 — zero vs not instrumented.** `staleness.total` is `null` until `declareSource`; client
  metrics are `NOT_INSTRUMENTED` until a report has ever arrived. A dashboard showing "0 staleness
  detections" before L19 exists would be a lie with a green light on it.
- **T14 — exclusion, not inclusion.** Rejections: match `-mutation$`, don't list types. Traffic
  count: every Role must appear in the countability table, enforced by test. Both are ADR `0041`'s
  "what happens the next time the code grows".
- **T15 — no DCS truth on the wire** (ADR `0059`). Count records carry the FDR callsign; nothing in a
  metrics body may carry a track's callsign, type or coalition. Correlation stats are aggregates only.
- **T16 — P5.** The instrumentation config is read once and never written. Retention changes need a
  restart; say so in the ADR and the wip note. Don't add a "set retention" endpoint.
- **T17 — `nlaStatusFor`, not `_stampStrip`.** The latter notifies `nlaStatusMonitor`
  (`efsp-ws.js:74–78`) and would suppress a status re-send the client actually needs.
- **T18 — do not grow `efsp-board.json`.** `_persist` runs after every Mutation; metrics there would
  cost every Mutation and put the Board at the mercy of a metrics bug.
- **T19 — `getStats().rate` is null on an empty board**; `null × eligible` is `0` in JS arithmetic.
  Skip the sample, don't multiply it.
- **T20 — merge neighbours.** L7 edits `server.js:432–456` and `:477–506` and adds `setOnEfspChange`
  inside `ws-hub.js:_onMessage`, keyed on `result.broadcast`. Your tap returns the wrapped result
  untouched, and your two new message types return `{ ack }` only, so L7's hook is unaffected. L1
  edits `index.js:262/272`; you don't touch them.

## 10. Open questions — take the default, log it under *Defaults taken*, carry on

- **Q1. Where the tap is installed.** Default: `createEfspInstrumentation` reassigns
  `efsp.handleMessage`/`efsp.onDisconnect` on the facade from server.js; `index.js` untouched.
  Alternative: wrap at `index.js:262` — rejected because L1 edits that exact line this wave.
- **Q2. Should Strip-op refusals be written to the Mutation log?** Default: **yes**, from the tap,
  `ok:false, source:'wire'`, for refused `efsp-mutation`s and wire-level `NOT_HOLDING_POSITION` on any
  type; store-level refusals of the other three stores are not duplicated. Known remainder: the
  class-based `PERMISSION_DENIED` refusals at `efsp-ws.js:403–405`/`:470–472` stay unlogged (the tap
  cannot tell them from store refusals by reason alone) — note in wip.
- **Q3. Traffic-count unit.** Default: one record per DROPPED ATC Strip per Facility; report
  `flights` (headline) and `aircraft` (Σ flightSize); a converted arrival is one record with
  `legs: 2`. Real counts differ on whether a formation is one operation or N and whether a sortie is
  one or two — the guide settles neither, so report both and mark `[SOURCE-DEFINED]`.
- **Q4. Countability thresholds.** Default: DEPARTURE counted from `DEPARTED`/`HANDED_OFF`, ARRIVAL
  from `LANDED`/`TAXI_IN`, OVERFLIGHT always, MISSION never, rejected replicas never; excluded drops
  are recorded with a reason, not discarded.
- **Q5. Where home airports live.** Default: `config/efsp-instrumentation.json`,
  `trafficCount.homeAirports`, shipped `{ "INCIRLIK": ["LTAG"] }`, everything else `UNKNOWN`. Not
  `facility-config.js` (serialised through L1/L13/L17). If L1's runway inventory names the airfield,
  the integrator may later point this at it — a new ADR (P4).
- **Q6. Hour bucket time.** Default: `droppedAt`. Alternative: takeoff/landing time with a §10.5-style
  fallback chain — deferred until L16's provenance chains exist.
- **Q7. Retention periods.** Default: Mutation log 30 days (guide §11.3), metrics buckets 30 days,
  traffic-count records 400 days (a year-on-year month always available). All `[SOURCE-DEFINED]`,
  all config, all restart-to-apply (P5).
- **Q8. Do metrics survive a restart?** Default: hour buckets and `sources` yes (own file, 60 s
  flush, ≤ 60 s loss on crash); per-WS-session records no.
- **Q9. What is a transfer?** Default: `TransferStrip` + transfer-shaped `InvokeNla`; every refusal,
  including `STALE_REV` and `NOT_HOLDING_POSITION`, is a failure with its reason as the cause;
  cross-Facility `HANDOFF` excluded (a REJECT is a decision, not a failure); `SystemReassign` reported
  separately.
- **Q10. `recordMet()`'s caller.** Default: not yours — L7 adds it inside the monitor; you only read
  `getComplianceStats()` through the getter. If L7 took its escape hatch, obligations show `missed`
  only; do not wire it yourself.
- **Q11. Alert scramble before L13.** Default: the latch in §5.3 plus `noteFdr(fdrId)`; write in
  `docs/wip/L5.md` that L13 must route `alertStatus` writes through a logged Strip Mutation or call
  `efspInstrumentation.trafficCount.noteFdr(fdrId)`. Until L13, the category is correctly always 0.
- **Q12. Client transport.** Default: WS (`efsp-metrics-report` / `efsp-metrics-request`) for L15, plus
  HTTP GETs for reads (L15 may use either; L6 and curl use HTTP). No HTTP POST for reports — it would
  need a second identity check and a proxy line for no gain.
- **Q13. Keying by `positionId`.** Default: yes, with `facilityId` carried inside each entry, guarded
  by the uniqueness test in step 6. If a future Facility reuses an id the test fails and the key
