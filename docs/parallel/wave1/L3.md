## 1. Mission

parsed ATO to:

1. a **`createFdr` seed** per flight: the flat object `FdrStore.createFdr(seed)` already accepts

## 4. USMTF ATO: what the sources say (and do not)

**Primary source used: the 455 vAEW "ATO, ACO & SPINS Guide", ATO page**
(<https://wiki.455aew.com/books/ato-aco-spins-guide/page/ato>). This is a DCS virtual-squadron
community wiki, very likely the "DCS community wiki" §9.9 means. It has no author attribution or
disclaimer.

- Combined Ops' note on its generated ATO (<https://www.combinedops.org/post-19-iff-sif-codes-added-to-air-tasking-order>)
  confirms the IFF encoding.
- A USMTF-2000 primer snippet surfaced by search shows the `AMSNDAT/N/…` variant
  (<https://www.coursehero.com/file/p1uhom/USMTF2000-OPER505-th-TRS-TRAINING-MSGIDATOWILLIAMSATOTRGMARCHG-AKNLDGNO/>,
  paywalled; seen only as a search excerpt).
- **MIL-STD-6040 itself was not consulted.** It is not publicly available. Everything below is
  community-sourced and must be labelled so.

### 4.1 Syntax

- A **set** is `NAME/field/field/…//`. `/` separates fields, and `//` terminates the set.
- `-` is an empty field. The wiki's own example also has `/ /` (a space) as an empty field.
- A field may carry a **descriptor**: `KEY:VALUE`, e.g. `ACTYP:F15C`, `DEPLOC:LBNA`,
  `PFREQ:156.5`, `KLBS:30.0`, `NAME:BLUE TRACK`, `ARCT:011000Z`, `FROM:…`.
- **Columnar sets** have a name starting with a digit (`5REFUEL`, `7CONTROL`, `9PKGDAT`). The name
  is alone on its line. The next line is a header row of column names, each prefixed by `/`. Then
  come data rows, one per line, each starting with `/`, with values space-padded for alignment. The
  last row ends with `//`.
- A long linear set may wrap across lines. Sets are uppercase.
- **Date-time group (DTG)**: `DDHHMMZ`, optionally followed by a three-letter month and optionally
  a four-digit year. Examples: `011000Z`, `011000ZOCT`, `010600ZOCT1998`. TIMEFRAM carries the full
  form, and other sets often omit the month or year.

### 4.2 Message order

The wiki says: header `OPER`, `MSGID`, `AKNLDG`, `TIMEFRAM`, then `TASKUNIT` blocks, each followed
by its missions. `TASKUNIT` "is used only once and is followed by missions information assigned to
this unit". A mission starts at `AMSNDAT`, and the wiki says every mission has at least `AMSNDAT`,
`MSNACFT` and exactly one of `GTGTLOC`/`MTGTLOC`/`SHIPTGT`/`ESCDATA`/`RECCEDAT`/`AIRMOVE`/`AMSNLOC`.
Package sets (`9PKGDAT`, `PKGCMD`) sit outside missions. The wiki does **not** give the relative
order of tanker sets.

**IFF/SIF encoding.** The first digit is the mode, and the rest is the code. From the wiki:
`20001` = Mode 2 code 0001, and `30111` = Mode 3 code 0111. Combined Ops: *"3 digit for Mode 1 and
5 digit for Mode 3, for example 131 means Mode 1, code 31, 35011 means Mode 3, code 5011"*. So
Mode 1 is `1` + two octal digits, and Modes 2 and 3 are the mode digit + four octal digits.
`ARINFO`'s tanker IFF appears with a descriptor, `B:34010`.

Sets the wiki documents that this lane **recognises but does not map**: `GTGTLOC`, `MTGTLOC`,
`SHIPTGT`, `RECCEDAT`, `PTRCPLOT`, `ASUPTFOR`, `ASUPTBY`, `AIRMOVE`, `FACINFOR`, `URMKREF`. The
free-text sets `AMPN`, `GENTEXT` and `NARR` are kept only as raw remarks.

| `atobrief-adapter.js` | parsed atobrief package **object** → `AtoDocument` | `usmtf-time.js` (HHMMZ helpers) |
| `ato-ingest.js` | facade: `parseAtoText`, `ingestAtoText`, `ingestAtoBrief`. Holds the **source caveat** header | all of the above |

The rule that keeps this pure: **do not require** `fdr-store.js`, `airspace-config.js`,
`stereo-routes.js`, `facility-config.js` or anything else that reads files at require time. Where
you need one of their constants (the callsign rule, `MAX_FREE_TEXT`), duplicate it with a comment
citing `fdr-store.js:67` / `:76`, and add a **parity test** (§6, step 6) that imports both.

### 5.3 Tokenisation (`usmtf-tokenize.js`)

`tokenize(text) → { sets: Set[], warnings }` where
`Set = { name, kind: 'linear'|'columnar'|'freetext', fields: Field[], header?: string[], rows?: Field[][], line, endLine, raw }`
and `Field = { raw, value, key, empty }`. Rules:

1. Strip a BOM. Normalise `\r\n` and `\r` to `\n`. Cap input at **1 MiB**. Over the cap, return no
   sets and error `INPUT_TOO_LARGE`. A non-string input gives error `NOT_TEXT`.
2. Scan with a cursor, not one big regex. Skip whitespace between sets.
   - A set starts at `[0-9A-Za-z]`, and its name runs to the first `/` or newline. Upper-case the
     name.
   - A set ends at the next `//`.
   - Anything else between sets (stray punctuation, a trailing `.` after `//`, which the wiki's own
     GENTEXT example has) gives info `STRAY_TEXT` and is skipped up to the next line start.
   - **End of input with no `//`** gives warning `UNTERMINATED_SET`. The partial set is still
     returned with `terminated: false`. The structure pass may use it, but must attach the warning.
3. **Free-text sets** (`AMPN`, `NARR`, `GENTEXT`, `RMKS`): do not split on `/`. The body up to `//`
   is one field. It may contain single slashes. Truncate at 2000 characters with info
   `FIELD_TRUNCATED`.
4. **Columnar sets** (name starts with a digit):
   - Split the body on newlines. Each non-blank line that starts with `/` (after trimming) is a row.
     Split it on `/`, drop the leading empty field, and trim every cell.
   - The **first row is the header**. Upper-case it and keep it as `header` column names.
   - Rows whose cell count differs from the header's give warning `COLUMN_COUNT` and are kept
     positionally.
   - A columnar set written on one line cannot be told apart from linear. Treat it as having no
     header, with warning `COLUMNAR_NO_HEADER`, and use positional columns.
5. **Linear sets**: split the body on `/`. Newlines inside a set are wrap points: replace
   `\n\s*` with the empty string, because USMTF wraps inside fields.
   - Each field is trimmed.
   - `-`, an empty string and whitespace are all `empty: true, value: null`.
   - A descriptor is `/^([A-Z][A-Z0-9]{0,5}):(.*)$/`. That gives `key`, and `value` becomes the part
     after the colon, trimmed. A **DTG never contains `:`**, and coordinates like `2840N08040W` do
     not either, so they stay bare.
   - Upper-case values, except in free text.
6. No regex with nested quantifiers anywhere. Add the pathological-input test in step 1.

### 5.4 Per-set extraction (`ato-sets.js`)

One function per set, each `(set, ctx) → { value, warnings }`, where `ctx` holds the time
resolver. Lookups are **descriptor-first, then positional**: find a field by `key` where the
community list gives one, and fall back to position only for bare fields. Record the fallback in a
`heuristics: []` array on the result, so the ADR can list every place the parser guessed.

- **`AMSNDAT`**
  - Variant detection: if field 1 matches `/^[A-Z]$/`, it is **variant B**. Shift by one, and read
    the DTG that directly follows `DEPLOC:`/`ARRLOC:` when it is DTG-shaped. Otherwise use variant A.
    Record `variant` and add info `AMSNDAT_VARIANT_B`.
  - Output: `{ missionNumber, amcMissionNumber, packageId, isPackageCommander: field==='MC',
    missionType: { primary, secondary }, alertStatusRaw, departure: { location, timeUtc, raw },
    recovery: { … } }`.
  - `DEPLOC`/`ARRLOC` are found **by key**, never by position.
  - A missing mission number is error `MISSING_MISSION_NUMBER`, and that mission is skipped.
- **`MSNACFT`**: `{ count, aircraftType, callsignRaw, callsign, config: { primary, secondary },
  datalinkCode, iff: { modeOne, modeTwo, modeThree } }`.
  - `count`: an integer ≥ 1. Otherwise warning `BAD_AIRCRAFT_COUNT`, and use 1.
  - `aircraftType`: the `ACTYP:` value, else field 2 bare.
  - `callsign`: see §5.6.
  - **IFF, `[SOURCE-DEFINED]` heuristic** (the wiki's own list and example disagree):
    - Walk back from the last field, taking at most **3** fields, while each is empty or
      IFF-shaped. IFF-shaped is `/^(?:[A-Z]{1,2}:)?(?:1[0-7]{2}|[23][0-7]{4})$/`. Those fields are
      the IFF slots.
    - The mode is the first digit, and the code is the rest.
    - A second token for the same mode gives warning `IFF_DUPLICATE_MODE`, and the first one wins.
    - A 5-digit token starting `1`, or a token with a non-octal digit, gives warning `IFF_MALFORMED`
      and that mode is `null`.
  - **Datalink**: among fields 6..(first IFF slot − 1), take the **last non-empty** one. If more
    than one is non-empty, add info `DATALINK_AMBIGUOUS`. For the wiki example this yields `27`.
  - Mode 3 is checked with `isValidCodeFormat`, `isReserved` and `isSynthetic` from
    `../code-allocator` (§3.4).
    - Reserved gives warning `MODE3_RESERVED`. Keep the value, because the controller must see what
      the ATO said.
    - Synthetic gives warning `MODE3_SYNTHETIC`. `code-allocator.js:92` would refuse it as an
      assignment, and crc-sync gives this block to AI transponders.
  - Mode 1: two octal digits. If `opts.modeOneMax === '73'` and the second digit is above 3, add
    warning `MODE1_OUT_OF_RANGE` but keep the value. Guide §3.10.3 rule 5 says the range is
    disputed and belongs in facility config. That config is not yours, so the option is only a
    hook.
- **`AMSNLOC`**: `{ start: {utc, raw}, stop: {utc, raw}, locationName, altitudeFt, priority }`.
  - `altitudeFt` = integer × 100 (hundreds of feet MSL). A non-integer gives `null` and warning
    `BAD_ALTITUDE`.
  - `stop < start` after resolution gives warning `VUL_END_BEFORE_START`. Keep both values and do
    not "fix" them.
- **`CONTROLA`**: `{ type, callsign, callsignRaw, primary, secondary, reportInPoint }`.
  - `type` must be `AWAC`/`CRC`/`OTR`. Anything else gives warning `UNKNOWN_AGENCY_TYPE`, and the raw
    value is kept.
  - `primary`/`secondary` are `{ freqMhz: number } | { designator: string } | null`, taken from
    `PFREQ`/`PDESIG` and `SFREQ`/`SDESIG`.
  - `reportInPoint`: the `NAME:` value if present, else the first bare non-empty field after the
    secondary.
  - Do **not** import `airspace-config.isValidFrequency` (load-time I/O). Parse the number, and add
    warning `BAD_FREQUENCY` when it is not finite.
- **`ARINFO`**, in the receiver's mission: `{ tankerCallsign, tankerCallsignRaw, tankerMissionNumber,
  tankerModeThree, arcp, altitudeFt, arctUtc, endArUtc, offloadKlb, primary, secondary, tankerType,
  system, tacan }`.
  - Read these by key: `NAME` → arcp, `ARCT`, `NDAR`, `KLBS`, `PFREQ`/`PDESIG`, `SFREQ`/`SDESIG`,
    `ACTYP`.
  - Read these by position: fields 1 (callsign), 2 (tanker mission number), 3 (IFF, descriptor
    allowed; take only Mode 3) and 5 (altitude, hundreds of feet).
  - `system` is the first field equal to `BOM`, `CDT`, `BOOM` or `DROGUE`.
  - `tacan` is the first field matching `/^\d{1,3}-\d{1,3}$/`. The two numbers differ by 63 in the
    wiki's examples (`18-81`, `29-92`), which fits an air-to-air TACAN pair. Store the raw string
    and do not interpret it.
  - Ignore the remaining unknown fields silently.
- **`REFTSK`**, in the tanker's mission: `{ system, totalOffloadKlb, alertOffloadKlb, primary,
  secondary, tacan }`. Of the two `KLBS:` fields, the first is total and the second is alert.
- **`5REFUEL`**, in the tanker's mission: rows → `{ receiverMissionNumber, receiverCallsign(+Raw),
  count, aircraftType, offloadKlb, arctUtc, sequence, fuelType, system }`.
  - Map columns **by header name** (`MSNNO`, `RECCS`, `NO`, `ACTYPE`, `OFLD`, `ARCT`, `SEQ`, `TYP`,
    `ARS`), with positional fallback in that order.
  - Strip the descriptors `AC:`, `KLB:` and `A:`.
- **`7CONTROL`**, in the controlling agency's mission: rows → `{ missionNumber, callsign(+Raw),
  count, aircraftType, missionType, onStationUtc, reportInPoint }`. Columns by header name
  (`MSNNO`, `ACSIGN`, `NO`, `ACTYPE`, `MSNTY`, `TOSTA`, `RIP`).
- **`9PKGDAT`**: rows → `{ packageId, unit, missionNumber, primaryMissionType, count, aircraftType,
  callsign(+Raw) }`.
- **`PKGCMD`**: `{ packageId, unit, missionNumber, callsign(+Raw) }`.
- **`TASKUNIT`**: `{ unit, location }`, with `ICAO:` stripped. **`TIMEFRAM`**: FROM/TO/ASOF.
  **`MSGID`**: as in §4.3. If `qualifier === 'CHG'`, add info `ATO_CHANGE_MESSAGE`. Amendment
  semantics are L14's call.

### 5.5 Structure (`ato-structure.js`)

Walk the sets in order, keeping `currentTaskUnit` and `currentMission`.

- `OPER`/`EXER`/`MSGID`/`AKNLDG`/`TIMEFRAM` are header sets. Build the time resolver from
  `TIMEFRAM` **before** extracting anything else. Do a pre-pass: find `TIMEFRAM` first, wherever it
  sits.
- `TASKUNIT` closes the current mission and sets `currentTaskUnit`. The unrecognised
  `TASKCTRY`-style grouping sets close the current mission and are listed in `unmappedSets`.
- `AMSNDAT` closes the current mission and opens a new one:
  `{ ...amsndat, taskUnit: currentTaskUnit, aircraft: [], location: null, control: null,
  arReceiving: [], tanker: null, controlledRows: [], remarks: [], lines: [] }`.
- `MSNACFT` → `aircraft.push`.
  - A second `AMSNLOC` or a second `CONTROLA` gives warning `DUPLICATE_SET`, and the first one wins.
  - `ARINFO` → `arReceiving.push`.
  - `REFTSK`/`5REFUEL` → `tanker.reftsk`/`tanker.receivers`.
  - `7CONTROL` → `controlledRows`.
  - `AMPN`/`GENTEXT`/`NARR` → `remarks`.
- A mission-scoped set with no open mission gives warning `SET_OUTSIDE_MISSION` and is dropped.
- `9PKGDAT`/`PKGCMD` close the current mission (they belong to the package section) and feed
  `packages`.
- Unknown set names give info `UNKNOWN_SET` and go into `unmappedSets`. The known-but-unmapped sets
  (§4.3) are listed with no warning.
- At the end:
  - A mission with no `MSNACFT` gives warning `MISSING_MSNACFT`, and the mission is kept with zero
    lines.
  - A mission with none of the "location" sets gives info `NO_LOCATION_SET`.
  - Two missions with the same number give warning `DUPLICATE_MISSION_NUMBER`. Keep both, and give
    the second one a line id with a `~2` suffix.

### 5.6 Callsigns

`normaliseCallsign(raw)` upper-cases, then removes spaces, `-` and `_`. The result must match
`/^[A-Z0-9]{1,7}$/`, the same rule as `fdr-store.js:67`. If it does not, the line is
**`seedable: false`**, with warning `CALLSIGN_INVALID` naming the raw and normalised forms. The
line is still returned (with `seed.callsign = null`) so L14 can show it and let the controller
type a callsign.

**Do not invent an abbreviation** (`LIGHTNING 01` → `LTNG01`). That would be a fabricated
convention, which is defect D11 (open question Q4). Every join (5REFUEL receiver, 7CONTROL, ARINFO
tanker) matches on **mission number first**, then on the normalised callsign. It never matches on
the raw callsign.

### 5.8 The atobrief adapter (`atobrief-adapter.js`)

`fromAtoBriefPackage(pkg, opts) → AtoDocument` (`source: 'ATOBRIEF'`). The input is a plain object
and nothing here parses YAML. Never throws. Mapping:

- **Date.** `header.ato_date` (`YYYY-MM-DD`) plus each `'HHMMZ'` gives epoch ms. With no
  `ato_date`, use `opts.referenceUtc`'s date. With neither, the value is `null` with warning
  `TIME_UNRESOLVED`.
  - An end time earlier than its start rolls forward one day, with info `ROLLED_PAST_MIDNIGHT`.
  - `'0240'` without a `Z` (`Flashbang 1.6.yaml:185` has one) is accepted with info
    `ZULU_ASSUMED`.
- **Per mission**:
  - `mission_number` → missionNumber, verbatim (`MSN2106`).
  - `callsign` → §5.6 (`SHADOW-1` → `SHADOW1`, `Knight 2` → `KNIGHT2`).
  - `aircraft.count`/`type` → one MSNACFT.
  - `aircraft.loadout` → `scl.primary`.
  - `mission_type` → primary.
  - `unit` → the task unit.
  - `deploy`/`recovery` → departure/recovery location.
  - `control.agency_id` → `registry.control_agencies[id]`. That gives `callsign` →
    controllingAgency, `type` (`AWACS`/`CRC`, kept verbatim) and `primary_freq_mhz` (a string, so
    parse it).
- **Vul window.** Use the same derivation as `atobrief/public/js/app.js:524`–`:545` (IP steerpoint
  time → start, EP → end). If those are missing, fall back to the first `targets[].tos`/`toffs`,
  then to `tot_net`/`tot_nlt`. Record which one was used in provenance (`ATOBRIEF_IP_EP`,
  `ATOBRIEF_TOS`, `ATOBRIEF_TOT`), and add info `VUL_IS_IP_EP` whenever IP/EP was used. **It is not
  AMSNLOC's meaning**, and the controller should know.
- **IFF.** Find the SPINS section whose `title` matches `/\bc3\b|iff\b/i` (the same test as
  `editor-spins.js:65`). For each `table.rows` entry `[msn, mode, code]`, match it to a mission by
  `mission_number` with the `MSN` prefix removed (see `build_doc.py:238`). Modes `1`/`2`/`3` go to
  `identityAto`. The same reserved/synthetic warnings apply (§5.4), and they will fire on miztoyaml's
  random codes. That is correct.
- **Refuel.** For each `refuel[]` entry, `tanker_id` → `registry.tankers[]` by callsign. The
  receiver gets an `arInfo.asReceiver` entry: tanker callsign; `time_from` → arct;
  `time_to` → endAr; the tanker's `altitude_ft`, `freq_mhz` and `tacan`.
  - The ArLink has `tankerMissionNumber: null` and `resolved: 'TANKER_NOT_A_MISSION'`. Tankers have
    no mission line in this format.
- **Package**: none. **Mode 1/2**: none. **Alert**: `NONE`. **Datalink**: none. Say so in the
  module header, so nobody later "fixes" the missing fields by inventing them.

## 9. Traps

1. **The seed is a whitelist you do not control.** `createFdr` silently ignores unknown keys
   (§3.1). A test that "passes modeOne in the seed" proves nothing. Keep the non-seed values out of
   `seed`, and assert that the seed's keys are a subset of the known list.
2. **Never put the ATO's Mode 3 into the seed as a beacon.** §3.2 rule 3 and §3.10.2 rule 9 say a
   code is never accepted from a filed plan. §3.10.3 rule 3 says ATO-vs-ATC Mode 3 is a
   **reconciliation** where "the ATC code is authoritative by default" and the panel "MUST NOT
   silently prefer either". `createFdr` mints regardless. L14 decides.
3. **M-number collision.** The guide's M4/M5/M7 are not `MISSION_BLOCK_MAP`'s M4/M5/M7 (§3.2).
   Name things by field. A comment such as "M4 IFF" next to code that ends up on Block `M4` (the
   beacon) is the exact confusion ADR 0052 exists to stop.
4. **Load-time I/O imports.** Requiring `fdr-store.js` from the parser pulls in `airspace-config.js`
   and `stereo-routes.js`, which read config at require time. The parser becomes environment-
   dependent and L14's client-side reuse gets harder. Only `code-allocator.js` is safe.
5. **The wiki contradicts itself three times**: AMSNDAT (list vs multi-set example), MSNACFT
   (datalink position), and ARINFO (list off by one, `AE20`). Use descriptors wherever they exist,
   use shape-based detection for IFF, and list every heuristic in the ADR as `[SOURCE-DEFINED]`
   (§0.2 of the guide forbids presenting these as doctrine).
6. **Month-less and year-less DTGs.** `140400Z` inside 5REFUEL has no month, and `011005Z` in the
   wiki has neither. Resolve against TIMEFRAM, and handle the month and year rollover. Do not use
   `Date.now()` as a silent default: a parser whose output depends on the day the test runs is a
   flaky test. `opts.referenceUtc` is explicit, or the result is `null` with a warning.
7. **`new Date(y, m, d)` is local time.** Use `Date.UTC` throughout. Month index is 0-based.
8. **Columnar rows are padded.** Trim every cell. `/4 /AC:F16C` has `4 ` with a trailing space, and
   `NO/ACTYPE` in the header is two columns, not one.
9. **Callsigns: raw vs normalised.** `VIPER 11` in the ATO is `VIPER11` on the FDR. A join on raw
   text silently fails to join. Mission number first, always.
10. **Formation ≠ N records** (§3.2 rule 2). `MSNACFT/4/…` gives one line with `flightSize: 4`.
11. **An AR link is not MARSA.** Do not emit anything that reads as a declaration (§8.3's key
    check). ADR 0051 made MARSA an edge with its own store and an interlock that voids.
12. **atobrief's vul window is IP→EP.** Tankers have no mission number, the IFF codes are random
    (and may be reserved), and `yaml-format.md`'s 4701 formula is stale (§3.6). Warn, do not fix.
13. **D-4 (guide §14.1).** Flight plans are filed independently of the ATO, and ATO ingest "MUST
    NOT be a prerequisite for clearance delivery". That is why DEPLOC/ARRLOC and AMSNLOC altitude do
    **not** go into `filed.*` (Q5). An ATO that fills `filed.departureAirport` would quietly make the
    tower chain depend on it.
14. **`mission.*` values are free text on the wire.** A controller editing Block `M6` today writes
    whatever the client sends. Your epoch-ms numbers will render raw unless L14 adds a formatter.
    That is L14's problem, but write it in `docs/wip/L3.md` "for L14" so it is not rediscovered.
15. **Never throw.** Wrap the facade in `try/catch`. A caught exception becomes error
    `INTERNAL_ERROR` with `ok: false`. The **test** must still fail if that code ever appears for
    §7.1 or §7.2, or the catch would hide real bugs.
16. **ReDoS.** No nested quantifiers. The 1 MiB cap plus the pathological test in step 1 keep this
    honest.
17. **`MSGID … /CHG/`.** An ATO change message amends a previous ATO. Surface it with info, and do
    not implement amendment. That needs the Board, which is L14's.
18. **Do not grow scope into ACO, targets or AIRMOVE.** List them in `unmappedSets`, and stop there.

  - **Default:** `seedable: false` plus `CALLSIGN_INVALID`. Keep the raw value, and invent no

  - The alternative, a configured abbreviation table, is squadron data. It can be raised to the
    human, because DCS group names like `Enfield 1-1` hit this constantly.

  - **Default: no.** They go in `ato.*` only, because of D-4. A mission line is a plan, not a filed

  - **Default:** epoch ms numbers, like every other `*Utc` field on the FDR, with the raw DTG kept in

    facility config, which is not this lane's.
- **Q8: How does AMSNDAT's air alert status map to `military.alertStatus`?**
  - **Default:** empty gives `NONE`, and any value gives `ALERT`. The ATO never yields `SCRAMBLE`,

  - **Default:** yes, and only when the mission has no CONTROLA. The fill is labelled in provenance
    and flagged with info.
- **Q12: The Annex files cited by §9.9 are not in the repo.**
  - **Default:** cite as the guide does, and add nothing attributed to the Annex. Record the gap in

- **Q13: MSNACFT datalink position (the wiki's list says field 6, its example uses field 7).**
