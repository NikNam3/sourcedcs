## 5. Job (b): the vm read instead of the scrape

### 5.1 Design

Build one lazily created sandbox that loads **only `bay-view.js`**. I verified that it evaluates
top-level with just `console`, `module`, a stub `document` and `window`. Read values by *evaluating
their names* in that context, and deep-copy the result out of the sandbox realm.

**The cross-realm trap.** `node:assert/strict`'s `deepEqual` is `deepStrictEqual`, which compares
prototypes. An array created in a vm context has that context's `Array.prototype`, so
`assert.deepEqual(vmArray, ['APP','CTR'])` **fails** even when the contents match. I verified that.
Copy the value out first with `JSON.parse(JSON.stringify(...))` or `[...arr]`.

### 5.2 Code (verified: 13/13 after 5.3 and 5.4)

Replace `efsp-coordination-client.test.js:72-99` (both scrape tests and their shared comment block)
with the following, keeping each test's **title unchanged**:

 * docs/adr/0055 made for the compact-Block list (efsp-ui-reachability.test.js's
 * clientSandbox). Top-level `const`s are lexical bindings, not properties of
 * the vm context, so they are read by evaluating the name in that context; and
 * the arrays come from the sandbox's realm, so they are copied before a

let _bayView = null;

      console, module: { exports: {} },

    vm.runInContext(require('fs').readFileSync(file, 'utf8'), _bayView, { filename: 'bay-view.js' });
  }
  return JSON.parse(JSON.stringify(vm.runInContext(name, _bayView)));
}

## 9. Traps

1. **`const` is not a vm context property.** Evaluate the name (`vm.runInContext('X', ctx)`), or you
   will read `undefined` and chase a phantom. The same holds for `let` (reachability `:62-66`).
2. **Cross-realm arrays fail `assert.deepEqual`** (strict). Copy them out first.
3. **The Board is durable across `createEfsp()` calls in one file.** Use `freshEfsp()` (§6.1). It
   matters most for vacate warnings, whose `count` covers every Strip the Position owns.
4. **`STALE_REV` masks the refusal you meant to test.** Re-read Strips via `tac(efsp, id)` before
   each `act`.
5. **The TOFI ACCEPT on ENTRY needs `separationRegime`** (ADR 0053). EXIT's ACCEPT needs the CTR
   side's `SREG` back at `ATC` *before* the EXIT proposal (military `:87-90`).
6. **`jumpTo` is `SetState`**, the unchecked escape hatch. Use it only to *set up* a state. Never use
   it to prove that a Position may advance, or AIC will look authorised when it is not (O1).
7. **`advance()` sleeps 410 ms.** Prefer `mustAct(... {kind:'InvokeNla'})` for a single press. Use
   `advance` only for back-to-back presses on one Strip, or the second press is silently swallowed
   by the double-tap guard.
8. **Which facilityId goes on the message.** `act()` sends the crew member's `facilityId`. A
   combined-controller crew object must carry the Facility of the *Strip* you are acting on (A6).
9. **Do not "fix" the stereo tags in the migration commit.** Changing `'input'` to `'select'` turns
   on the first-option rule and can change a picker's `.value` (§3.3, Q2).
10. **Do not add to the end of `efsp-ui-reachability.test.js`**, and do not move its `require`s. L2
    owns the tail.
11. **Do not edit `efsp-scenario.mjs`.** `freshEfsp` and the tactical helpers stay local.
12. **Do not start or restart any crc-sync.** The memory note "restart crc-sync after backend
