## 2. Mission

**Done means:** any authenticated controller can open a **METRICS** dock panel that shows every
§11.5 metric with its target and whether it is met, for **this mission** and the **last hour** (H32),
plus the §11.4 traffic count by category, hour and aircraft type and whether it reconciles against the
Mutation log. The three metrics only a client can observe are now actually measured and reported to
crc-sync from every client, whether or not the panel is open:

- **search invocations** per Position (every search run from the Strip panel);
- **time-to-find**: from entering a Bay to selecting a Strip in it;
- **inputs per paper gesture** (offset, flip, highlight, attention).

A metric with no source says **not instrumented**, never `0`; a rate with no data says **no data**,
never `100%` (L5's T13, the correlation rate's "null, never 1.0"). Per-person breakdowns are never
shown (H35). ADR `0072` and `docs/wip/L15.md` are written.

**Out of scope:**

- Server aggregation, retention, the traffic count's rules, the Mutation-log rotation — **L5**. You
  read and render them. A server bug is recorded in `docs/wip/L15.md`, not fixed.
- Staleness detection (§10.4) — **L19**. You render L5's `staleness` block as it is.
- The soak harness (L6), obligation semantics (L7).
- Any change to Strip behaviour. Measurement hooks observe; they never change what a click does,
  never delay a Mutation, never raise a banner.
- Charts via a library. No new npm dependency, no CDN (the Electron app runs offline) — tables,
  numbers and small inline SVG sparklines only.

## 4. What exists

### 4.1 L5's contract (`docs/parallel/wave1/L5.md` §5.6, as shipped: `lane/L5-metrics` @ `21e54e6`, accepted as **S-L5**. **The contract is the test** `crc-sync/tests/efsp-metrics-contract.test.mjs`; L5's `docs/wip/L5.md` "For the integrator" lists every deviation from its briefing)

Two rulings changed it after the briefing, and L5 built them:
- **S-R2-3:** the server stamps each reported event on receipt (`metrics.js` `handleReport`, "client
  `at` is ignored"). There is no ±10 min check any more.
- **S-R2-4:** every bucket carries a `missionSession`; the request takes `missionSession` (default:
  the current one) and the body has a rolling **`lastHour`** block beside the session's metrics. **No
  `controllerId` and no `sessions[]` on the wire; `byPosition` stays.** (That settles H32 and H35 on
  the server; you only render.)

WS, intercepted by L5's tap; replies go to the sender only (the `ack` slot). The panel uses WS. The
same bodies are also served over HTTP — `GET /api/efsp/metrics?missionSession=&hours=` and
`GET /api/efsp/traffic-count?facilityId=&from=&to=&missionSession=&detail=1` (`auth.requireAuth`;
unknown `missionSession` → `404 NOT_FOUND`) — and **you add their two proxy lines to
`crc-desktop/app/server.js`** (the `:101–112` pattern, after the stereo-routes line) so they are
reachable from the renderer and from curl against the local app.

The ten deviations from L5's briefing, as shipped (L5 wip items 1–10): no
`rejectedMutations.sessions`; new top-level `missionSession`, `missionSessions[]`, `lastHour`; every
`byHour` entry is an object carrying `missionSession` (`systemReassigned.byHour` values are
`{ missionSession, total }`, not numbers); `transfers.inhibitedPress`; `windowHours` defaults to the
whole session, not 24; the `efsp-metrics` answer carries `ok` and on a bad query is `{ ok:false,
reason:'VALIDATION_ERROR', detail }` with `requestId` echoed; client `at` ignored; a duplicate
`reportId` is acked `{ ok:true, accepted:0, rejected:[], duplicate:true }`; the traffic body echoes
`missionSession` and its `records` carry no `actorId`; an unknown `missionSession` is `NOT_FOUND`.

```jsonc
// request → reply
{ "version": 1, "type": "efsp-metrics-request", "requestId": "<uuid>", "missionSession": null, "hours": null,
  "trafficCount": { "facilityId": "INCIRLIK", "from": 0, "to": 0, "missionSession": null } }   // trafficCount optional
{ "version": 1, "type": "efsp-metrics", "requestId": "<uuid>", "ok": true, "metrics": { … }, "trafficCount": { … } }
// a bad missionSession → { …, "ok": false, "reason": "NOT_FOUND" | "VALIDATION_ERROR", "detail" }

// measurements → ack
{ "version": 1, "type": "efsp-metrics-report", "reportId": "<uuid>", "facilityId": "INCIRLIK", "positionId": "GND",
  "events": [ { "kind": "SEARCH", "at": 0, "bayId": "gnd-pending" },
              { "kind": "TIME_TO_FIND", "at": 0, "bayId": "gnd-pending", "latencyMs": 2140 },
              { "kind": "GESTURE", "at": 0, "gesture": "OFFSET", "inputs": 1 } ] }
{ "version": 1, "type": "efsp-metrics-report-ack", "reportId": "…", "ok": true, "accepted": 3,
  "rejected": [ { "index": 1, "reason": "VALIDATION_ERROR", "detail": "…" } ] }
```

Validation (`metrics.js` `handleReport`): `reportId` a non-empty string ≤ 128 chars; a known
`facilityId`; the reporter must hold `positionId` there as **Primary or Observer** (else
`NOT_HOLDING_POSITION`); ≤ 100 events per report; `latencyMs` integer 0…600000; `inputs` integer
1…50; `gesture ∈ OFFSET FLIP HIGHLIGHT ATTENTION`; dedupe by `reportId`. **No search text is ever
sent.**

The metrics body's top level (`buildMetricsBody`): `{ ok, version, generatedAt, serviceStartedAt,
missionSession: { seq, theatre, startedAt, lastAt, current }, missionSessions: [...], windowHours,
hours: [...], sources: { client, staleness }, metrics: { … }, lastHour: { from, to, metrics: { … } } |
null }` — `lastHour` has the same metric shape with empty `byHour` series, and is `null` for a past
session.

The metrics body (L5 §5.6): `metrics.searchInvocations`, `timeToFind`, `gestureInputs` (with
`serverSetFlagMutations` as a cross-check), `correlation`, `rejectedMutations` (no per-controller data, S-R2-4), `staleness` (`NOT_INSTRUMENTED`, `total: null` until L19),
`transfers` (now with `inhibitedPress`, S-R2-5), `obligations`, `systemReassigned`. Each has `status ∈ COLLECTING | NO_DATA |
NOT_INSTRUMENTED` and a `target` (`TRENDING_DOWN`, `P95_BELOW_MS 3000`, `EQUALS 1`, `AT_LEAST 0.95`,
`AT_MOST 0.005`). Buckets keyed `YYYY-MM-DDTHH:00Z` (mission-clock hours, H11). The traffic body:
per Facility `totals` (`local + transient + unknown === flights`; formation, SUA traversal and alert
scramble are **overlapping subsets**), `byHour`, `byAircraftType`, `byRole`, `excludedByReason`,
`homeAirports`, a `policy` string, and `reconciliation { ok, expected, actual, missing, extra,
mismatched, backfilled, checkedAt }`.

## 5. Design

### 5.1 Two new client files

| File | What | Loaded |
|---|---|---|
| `crc-desktop/app/public/js/panels/efsp/efsp-metrics-client.js` | measurement: the three hooks' targets, the queue, batching, flushing, ack handling. **Always loaded and always running**, panel open or not | after `efsp-ws.js`, before `bay-view.js` |
| `crc-desktop/app/public/js/panels/metrics-panel.js` (the plan's name) | the dashboard: request/poll, render | after `airspace-panel.js`, before `app.js` |
| `crc-desktop/app/public/css/metrics-panel.css` | its styles, on `efsp-panel.css`'s tokens | a `<link>` after `efsp-panel.css` |

Both JS files export their pure parts under `module.exports` for node tests (the codebase's
`if (typeof module !== 'undefined')` idiom).

### 5.2 `efsp-metrics-client.js` — measuring

Public hooks (each null-safe, never throws — wrap bodies in try/catch → `console.warn`):

```js
noteEfspSearch(positionId, bayId)                   // from _runEfspSearch, non-empty query only
noteEfspBayVisible(bayId, positionId)               // from _renderBayTabs, every render (dedupes itself)
noteEfspStripSelected(stripId)                      // from _selectStrip / selectEfspStripById
noteEfspGesture(gesture, entryPoint, positionId)    // from the gesture entry points (5.4)
```

- **Queue per `(facilityId, positionId)`.** Resolve `facilityId` from `getEfspBays()`; drop (with one
  `console.warn` per session) an event whose Position is not currently held — L5 would refuse the
  report anyway.
- **Flush** every 10 s, or at 20 queued events, or on `beforeunload` (*default*, Q-L15-5): one
  `efsp-metrics-report` per `(facility, position)` with ≤ 100 events and a fresh `reportId`
  (`crypto.randomUUID()`). Prompt, because the server stamps on receipt (S-R2-3): a batch held
  across an hour boundary lands in the wrong bucket. If the socket is closed, keep the queue (cap 500
  events, drop oldest, count drops) and retry at the next flush; events queued for more than 5 min are
  dropped locally rather than stamped into a later hour (count them in `docs/wip/L15.md`).
- **Ack**: `efsp-metrics-report-ack` → one `console.warn` per distinct rejection reason per session;
  never a banner (§2: measurement must not talk to the controller).
- **`at` = `missionNow()`** for the log's sake only; the server ignores it (S-R2-3).

### 5.3 Time-to-find (*default* semantics, Q-L15-2; `[SOURCE-DEFINED]` in 0072)

"Strip selection latency after Bay entry" (§11.5), for the Pending-bay choke point (§4.3 D2):

- **Start**: a Bay *becomes visible* — `noteEfspBayVisible(bayId)` with a `bayId` different from the
  last visible one (or the panel just became visible). Stamp `performance.now()`.
- **Stop**: the first selection of a Strip **whose `bayId` is that Bay** (search results count for the
  search pseudo-Bay: a Strip selected from the search Bay stops the search Bay's timer). Emit
  `TIME_TO_FIND { bayId, latencyMs }` for the Bay's owning Position.
- **Abandon, no sample**: the controller leaves the Bay, hides the panel, or 10 min pass. Nothing is
  reported for an abandoned entry (L5's body has no field for it; count abandons locally and put the
  count in `docs/wip/L15.md`'s walk).
- **Not a sample**: a selection that *clears* (the toggle off), a selection caused by the arrivals
  line (`efsp-panel.js:1399` opens a Bay *and* selects: latency ≈ 0 and not a find), a Bay with no
  Strips.
- One sample per Bay entry.

### 5.4 Inputs per gesture (*default*: a static cost per entry point, Q-L15-3)

The guide's target is exactly one input per paper gesture (§7.3). Count what the controller actually
has to do at each entry point, declared as data in `efsp-metrics-client.js`, and report it every time
that entry point dispatches:

```js
// [SOURCE-DEFINED] — inputs a controller spends at each gesture entry point (ADR 0072).
const GESTURE_INPUT_COST = {
  'FLIP:dblclick': 1,            // a double-click is one input
  'ATTENTION:shift-click': 1,
  'HIGHLIGHT:contextmenu+swatch': 2,
  'OFFSET:menu': 2,              // open ⋯, click Offset
};
```

- Report `GESTURE { gesture, inputs }` with the looked-up cost. A future entry point (a keyboard
  shortcut) adds a row; a missing row is a test failure, not a silent 1.
- **This will show HIGHLIGHT and OFFSET over the ceiling. That is the finding, not a bug** — do not
  "fix" the count; write it into `docs/wip/L15.md` for the supervisor.
- Where the hooks go (§7): each entry point passes its key. The one-line change is at the call sites
  (`bay-view.js:855`, `:860`, `:2143`; `strip-view.js:625`'s `run`), each adding
  `noteEfspGesture(…)` **after** `_dispatchGesture` returns, only when it actually dispatched
  (`_dispatchGesture` returns early for a dead replica or no acting Position — make it return a
  boolean, one-line change, *default*, so the metric counts only gestures that happened).

### 5.5 The dashboard (`metrics-panel.js`)

- Registered as dock panel **`metrics`**, title `METRICS`, in the left cluster, openable from the
  PANELS list. Visible to **everyone authenticated**; it needs no Position (H35).
- **Poll only while visible**: `efsp-metrics-request` on open and every 30 s while the panel is on
  screen (the dock's visibility, like `_isEfspPanelShowing`); nothing when hidden. Ignore a reply
  whose `requestId` is not the latest.
- **Two windows, side by side (H32, S-R2-4): "This mission"** (`metrics`, the current
  `missionSession`) **and "Last hour"** (`lastHour.metrics`). A small selector lists
  `missionSessions` (theatre + start time) so a past mission can be read back (`lastHour` is `null`
  then; show "—").
- **One row per §11.5 metric, in the guide's order**, each: name, value, target, verdict.
  - Verdict: `MET` / `NOT MET` / `NO DATA` / `NOT INSTRUMENTED` / `TRENDING ↓/↑/→` for the
    trend-down metrics (compare the last three complete hours; *default*, `[SOURCE-DEFINED]`).
  - **Only `NOT MET` uses the warning colour** (ADR 0056: colour means something is wrong). A met
    target is plain text. `NOT INSTRUMENTED` and `NO DATA` are grey and say so in words.
  - A null rate renders `—`, never `0` or `100%`. `staleness` renders
    `not instrumented (L19)` until `sources.staleness` is set.
  - A small inline-SVG sparkline of the hourly series where the metric is hourly; no axes, a
    `title` with the numbers.
- **Per-Position detail** for search invocations and time-to-find (the guide asks "per Position"),
  folded by default (Q-L15-1, HUMAN). **Never** a per-controller row; the server sends none (S-R2-4),
  and a test asserts the view-model has no `controllerId` should one reappear.
- **Traffic count** section: Facility selector (defaults to the first held Facility, else INCIRLIK);
  totals as a partition line (`local + transient + unknown = flights`) and the overlapping subsets
  labelled as such ("of which: formation 3, SUA 2, alert scramble 1"); `aircraft` beside `flights`;
  by hour; by aircraft type; excluded drops with reasons; the `policy` string verbatim; a
  reconciliation line — "reconciles with the Mutation log ✓ (checked 1432Z)" or "does not reconcile:
  N missing, M extra" in the warning colour.
- Times displayed `HHMMZ` from the mission-clock bucket keys; never the local wall clock.
- `[SOURCE-DEFINED]` things (locality, trend rule, gesture costs) get a one-line footnote in the
  panel, not presented as doctrine.

## 11. Traps

- **T1 — The server stamps on receipt (S-R2-3).** A batch held for minutes lands in the wrong hour;
  flush promptly and drop stale events rather than send them.
- **T2 — Zero is not "not instrumented"** (L5 T13). Render `status`, never infer it from a number.
- **T3 — No search text on the wire**, not even truncated.
- **T4 — Measurement must not change behaviour.** No awaits in hooks, no exceptions escaping, no extra
  Mutations, no banners. A metrics bug must not be able to break a Strip click.
- **T5 — `_renderBayTabs` runs on every refresh**, not only on Bay changes: dedupe by the last visible
  Bay or every board delta restarts the time-to-find clock.
- **T6 — The arrivals line opens a Bay and selects a Strip in one click** (`efsp-panel.js:1399`):
  that is not a find; exclude it.
- **T7 — A report for a Position you do not hold is refused** (`NOT_HOLDING_POSITION`). Resolve the
  Position from the Bay the event happened in and drop events for Positions released in between.
- **T8 — `_afterSelectionChanged` is L14's line this wave.** Hook the two callers.
- **T9 — H35.** No per-controller rows, no controller ids in the view-model (the server sends none).
- **T10 — Colour means something is wrong** (ADR 0056): a met target is plain; `NOT MET` and a
  failed reconciliation are the only coloured things.
- **T11 — The durable e2e state.** Without the redirects, runs pollute each other through
  `crc-sync/state/efsp-metrics.json`.
- **T12 — Formation, SUA traversal and alert scramble are not a partition.** Never draw them as
  stacked shares of the total.
