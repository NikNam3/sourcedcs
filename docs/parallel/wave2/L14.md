## 2. Mission

**Done means:** a `TAC_C2` controller pastes (or drops) a USMTF ATO into the Strip panel, sees a
preview of every mission line with its warnings and the flights it could bind to, and with one
confirm gets one `MISSION` Strip per line in `tac-c2-tasked`, created through the existing
`CreateStrip` (ADR 0054), either on a new FDR or bound to a live flight by its Mode 3/A (callsign as
the fallback, H1). Each FDR carries the ATO's mission number, package, vul window, controlling agency
and IFF codes. Mode 1/2 are readable and **not writable by any ATC Position**. A tanker's refuelling
line and its receivers' Strips show a joined AR group; selecting one highlights the others, and
**nothing about the join declares MARSA or touches the separation regime**. Re-importing an amended
ATO updates what the ATO owns and never overwrites what a controller typed. WP7's three bullets are
asserted in tests; ADR `0071` and `docs/wip/L14.md` are written.

WP7 (`EFSPImplementationGuide.md:1388–1398`), verbatim, is your acceptance:

1. *An ATO fixture produces mission Strips with correct mission number, package, vul window,
   controlling agency and IFF codes.*
2. *A tanker's AR line and its receivers' Strips render as a joined group.*
3. *The community-source caveat (§9.9) appears in the parser's module documentation.* (L3 put it
   there; you assert it is still there and add it to every new module under `ato/`.)

**Out of scope — do not build, do not stub:**

- **Parsing.** L3 owns `crc-sync/src/efsp/ato/` parsing and mapping. You call it; you do not fork it.
  A parser bug is reported in `docs/wip/L14.md` for the supervisor, not fixed by you, unless it is a
  one-line fix the supervisor approves.
- **Any new Block, any edit to `block-map.js` or its parity test.** L13 holds that file in wave 2
  (plan §2). Mode 1/2, datalink and the rest render as read-only rows and a badge (§5.7), not Blocks.
- **`permission.js`.** L23 is the only wave-2 lane on it (S-L8). You *call* its exports; you do not
  edit them.
- **MARSA.** The AR join is not MARSA and writes nothing to the MARSA store or `fdr.tofi`.
- **ACO parsing, target geometry, AIRMOVE, ROZ/ACM.** Not in §9.9's table.
- **ATO authoring or export** (guide §12: ingest only in v1).
- **Coordination-instrument capture for a Mode 3 departure** (§3.10.3 rule 3's "six instruments").
  The conflict is surfaced; recording the instrument is a later slice (Q-L14-9).

### 5.1 Server module: `crc-sync/src/efsp/ato/ato-board.js` (new, yours)

```js
// [SOURCE-DEFINED] — where an ATO lands. Guide §9.8: "TAC_C2 works mission lines".
const ATO_IMPORT_ORIGIN = { facilityId: 'TACTICAL', positionId: 'TAC_C2', bayId: 'tac-c2-tasked', rackId: 'main' };

previewAto({ text, fdrStore, liveStrips, nowUtc })   // → PreviewResult, never throws, no side effects
planImport(preview, choices)                          // → ImportPlan | { ok:false, reason, detail }
bindCandidatesFor(line, fdrs, liveStrips)             // → [{ fdrId, key:'MODE3'|'CALLSIGN', callsign, beaconAssigned, strips:[{stripId, facilityId, role, ownerPositionId}] }]
atoTaskingFor(line, doc)                              // → the object fdrStore.applyAtoTasking takes (§5.4)
```

`PreviewResult`:

```js
{
  ok, textSha1, header: { operation, msgId, timeframe },     // from L3
  lines: [{
    lineId, missionNumber, callsign, callsignRaw, seedable,
    action: 'CREATE' | 'BIND' | 'UPDATE' | 'SKIP',            // the preselected default (§5.3)
    bindCandidates: [...], existingFdrId: string|null,         // UPDATE target (re-import, §5.6)
    changes: [{ path, from, to, ownedBy: 'ATO'|'CONTROLLER' }],// UPDATE only
    missing: ['PACKAGE', 'MODE1', …],                          // H1's per-mission list, from L3

```

### 5.2 Wire: two new message types, appended to `efsp-ws.js`

Both are new `case`s at the end of `handleMessage`'s switch and new `_handle…` functions appended at
the end of the file (plan §2 rule for `efsp-ws.js`). Add `efsp-ato-mutation` to `_subject` only if
you give it a subject; *default*: `{ atoMsgSerial }`.

```jsonc
// client → server: read-only, never logged, not a "-mutation" (L5's tap must not count it)
{ "version": 1, "type": "efsp-ato-preview", "requestId": "<uuid>", "actingPositionId": "TAC_C2", "text": "<USMTF>" }
// server → sender only (the ack slot)
{ "version": 1, "type": "efsp-ato-preview-result", "requestId": "<uuid>", "ok": true, "preview": { /* PreviewResult */ } }

// client → server: the import
{ "version": 1, "type": "efsp-ato-mutation", "clientMutationId": "<uuid>", "facilityId": "TACTICAL",
  "actingPositionId": "TAC_C2",
  "op": { "kind": "ImportAto", "text": "<USMTF>", "textSha1": "<from the preview>",
          "choices": [ { "lineId": "1101A#0", "action": "BIND", "fdrId": "…" },
                       { "lineId": "1202S#0", "action": "CREATE", "callsignOverride": null } ] } }
// server → sender
{ "version": 1, "type": "efsp-ato-ack", "clientMutationId": "…", "ok": true,
  "results": [ { "lineId": "1101A#0", "ok": true, "action": "BIND", "stripId": "…", "fdrId": "…" },
               { "lineId": "1901T#0", "ok": false, "reason": "VALIDATION_ERROR", "detail": "…" } ] }
// server → everyone: ONE efsp-board-delta, facilityId TACTICAL, every created Strip + every touched FDR
```

Handler rules (`_handleAtoPreview`, `_handleAtoMutation`):

1. **Session binding per Facility** — copy `_handleMutation`'s `:155–158` exactly: Primary at
   `actingPositionId` **at TACTICAL**. Not "Primary somewhere" (that is airspace/correlation/MARSA's
   rule; wrong here because every Strip lands on TACTICAL's Board).
2. **Origin check:** `actingPositionId === ATO_IMPORT_ORIGIN.positionId`, else `PERMISSION_DENIED`
   with a detail naming TAC_C2. Board-store's own `canMutate`/`canCreateStripRole` still run on each
   `CreateStrip`; this is the up-front, one-message refusal. Do **not** edit `permission.js` (L23).
3. **The server re-parses the text.** It never trusts seeds, codes or ATO fields from the client.
   `textSha1` must match the re-parse, else `STALE_REV` with detail "the ATO changed since the
   preview" (reuse an existing reason code — a new one renders raw in the refusal banner,
   `crc-desktop/tests/efsp-refusal-banner.test.js`).
4. **Choices are validated against the recomputed preview**: a `BIND` `fdrId` must be one of that
   line's recomputed `bindCandidates`; an `UPDATE` must target the line's `existingFdrId`.
5. Per line, in lineId order, through the **existing** Board path:
   `boardStoreFor('TACTICAL').applyMutation({ clientMutationId: \`${cmid}#${lineId}\`, op: { kind:
   'CreateStrip', bayId, rackId, role: 'MISSION', fdr: seed } | { …, fdrId } }, 'TAC_C2',
   session.controllerId)` where `seed` is `line.fdrSeed` with its two vul times re-dated (§5.8) and
   `callsign` replaced by the preview's `callsignOverride` when given. The derived
   `clientMutationId` makes a replayed import idempotent line by line (board-store's cache). Then `fdrStore.applyAtoTasking(fdrId, tasking, { by, source })`
   (§5.4). A refused line is reported and the others continue (*default*: best effort, per-line
   results).
6. One audit entry for the import itself: `mutationLog.record({ clientMutationId, op: 'ImportAto',
   facilityId: 'TACTICAL', actingPositionId, actorId, at: clock.now(), ok, atoMsgId, textSha1,
   lines: [{ lineId, action, ok, stripId, fdrId, reason }] })`. Never the full text (size). A refused
   import is logged `ok: false` too (the store convention since ADR 0040).
7. `persist()` once if anything applied. Ack to the sender; **one** `efsp-board-delta` in
   `broadcast` with every new/updated Strip (stamped through `_stampStrip`, `efsp-ws.js:74`) and
   every touched FDR. No `peerBroadcast`, no `marsaBroadcast`.
8. Handler-level idempotency: a bounded `Map(clientMutationId → ack)` (cap 200) so a replayed
   `ImportAto` returns the first ack without re-parsing.
9. Size: refuse text over L3's cap before parsing (`VALIDATION_ERROR`, "ATO text over 1 MiB").

`index.js` (registration only, append at the end of `ctx`, `:236–256`): `clock` and `mutationLog`.
Nothing else in `index.js` — there is **no new store** (§5.4 says why), so `_persist`/`_restore` are
untouched.

### 5.3 Binding on the Mode 3/A, callsign as the fallback (§9.8's bridge field, H1)

`bindCandidatesFor(line, …)` looks at **live non-MISSION Strips on every Board** (FDRs are shared,
ADR 0013) and their FDRs:

1. **`MODE3`**: `line`'s ATO Mode 3 is valid (4 octal, not reserved, not synthetic) and equals
   `fdr.identity.beaconAssigned`.
2. **`CALLSIGN`** (only if no MODE3 candidate exists): the line's normalised callsign equals the FDR's
   callsign.
3. Exclude an FDR that already has a live `MISSION` Strip on TACTICAL (one mission line per flight;
   board-store would refuse it anyway, `:433`).

Preselected action (*default*, Q-L14-4): exactly one candidate on either key → `BIND`, labelled with
the key; two or more → `CREATE` preselected and every candidate listed (**ambiguity is an answer,
not a tiebreak**, ADR 0046); none → `CREATE`. **Nothing binds without the controller's confirm** —
the preview is the confirm, one input for the whole ATO. That is what keeps this on the right side
of ADR 0054's rejection of *automatic* Mode 3/A binding (`0054…md:76`); say so in 0071.

**The ATO-first direction** (the ATO arrives before the flight is filed) is a *caller* change, as
ADR 0054 promised: when OPS files a DEPARTURE whose callsign matches an ATO mission FDR that has no
live ATC Strip, the create-strip toolbar offers "file against ATO mission `<msn>`" and sends
`CreateStrip` with `op.fdrId` (the bind path, no new code minted, no server change). *Default*:
build it as the **last** step (§6 step 8); drop it with a note if time runs short (Q-L14-10).

### 5.4 Where the ATO's values live: on the FDR, one new setter (no new store)

The shared `fdrId` is the link (ADR 0054), so the ATO's facts about a flight go **on that flight's
FDR**. That buys, for free: persistence and restore with the Board (`_persist` already writes
FDRs whole), the snapshot, the board-delta, per-Facility replicas and TOFI replicas seeing the same
answer, and a join keyed by `fdrId` exactly like MARSA and correlation. A separate `AtoStore` would
need its own delta, a `ws-hub.js` forward and `_persist`/`_restore` registration, and would be a
second place to ask "what is this flight's Mode 1" (Q-L14-3).

**`fdrStore.applyAtoTasking(fdrId, tasking, { by, atoRef })`** — appended to `fdr-store.js`
**immediately after `setMilitary()`** (`:832–861` at `cfcf344`). One dedicated writer, structurally
outside `WRITABLE_PATHS` and `MILITARY_WRITABLE_FIELDS`, on the `setTofi`/`setBeaconObserved`
template: it refuses unknown keys, validates, bumps `rev`/`updatedAt` once, and sets provenance
`'ATO'` on each path it writes. It writes:

| Target | From (L3's line) | Rule |
|---|---|---|
| `identity.modeOne`, `identity.modeTwo` | `extras.identityAto.modeOne/modeTwo` | ATO-owned, **read-only to ATC** (§3.10.3 rule 1). No other writer exists or may be added |
| `military.scl` | `military.scl` | verbatim |
| `military.arInfo` | `military.arInfo` + the document's `arLinks` | L3's `{ asReceiver, asTanker }` verbatim **plus** `links: [{ role: 'TANKER'\|'RECEIVER', peerFdrId\|null, peerMissionNumber, peerCallsign, windows }]`, resolved at import (`tankerLineId`/`receiverLineId` → the fdrId that line created or bound) |
| `military.alertStatus` | `military.alertStatus` | **only on a newly created FDR**, and only `ALERT` (the ATO never says `SCRAMBLE`); never on a bind or update (L13 owns the Block and its semantics this wave) |
| `fdr.ato` (new sub-object, created by this setter; readers treat absent as `null`) | `extras.ato` (minus `callsign`/`seedable`, which the FDR already answers) + `extras.identityAto.modeThree` and `.datalink` | `{ atoRef: { msgId, textSha1, importedAt, importedBy }, missionNumber, missionType, isPackageCommander, packageCommander, departure: { location, timeUtc, raw }, recovery, missionLocation, missionAltitudeFt, vulSource, vulRaw, targets, onStationUtc, reportInPoint, control, remarks, missingAcceptanceFields, iff: { modeThree }, datalink, warnings }` — every time re-dated per §5.8 |

**Contract C1 (L16 reads it):** `fdr.ato.departure.timeUtc` is epoch ms in-game Zulu, or `null`. L16's
§10.5 departure-time chain uses it as its `ATO` source. Do not rename it without telling the
supervisor.

Do **not** touch `createFdr`, `setField`, `WRITABLE_PATHS` or the stereo branch (L16's and L2's
areas). Do **not** add `ato` to `createFdr`'s literal: the setter creates it, the client and every
reader are null-safe (§12's "present and unpopulated" is satisfied at read, like `ensureMilitary`).

**The beacon code (ADR 0054's inherited question, Q-L14-1, HUMAN).** *Default*: on a **newly
created** FDR, if the ATO Mode 3 passes `codeAllocator.validateAssignment`, `applyAtoTasking` adopts
it as `identity.beaconAssigned` (releasing the code `createFdr` just minted), provenance `'ATO'`, a
duplicate being a warning (D23). If it fails (reserved, synthetic block 6000–6777, malformed,
absent), the minted code stays. On a **bind or update, `beaconAssigned` is never touched** — the ATC
code is authoritative (§3.10.3 rule 3); the ATO's code sits in `fdr.ato.iff.modeThree`.

### 5.5 The Mode 3 conflict (§3.10.3 rule 3)

When `fdr.ato.iff.modeThree` is non-null and differs from `identity.beaconAssigned`, **every** Strip
of that flight shows it: an `_stripAlerts` entry `{ key: 'ato', tone: 'attn', text: 'M3 ATO 4521',
reason: 'ATO tasks Mode 3 4521; ATC assigned 4533. The ATC code stands unless coordinated.' }` and
an `'ato'` key in `INDICATOR_ORDER` after `'conf'` (the `stca`/`conf` loop in `_buildIndicatorSlots`,
`strip-view.js:465–469`, renders alerts only for keys it names — add `'ato'` to that condition too). It clears when the codes
agree (a controller edits Block 5/M4, or a re-import changes the ATO's code). Nothing prefers either
code silently. The coordination-instrument capture is not built (Q-L14-9); 0071 says so and marks
the convention `[SOURCE-DEFINED]`.

### 5.6 Re-import (Q55(a): you diff by mission number)

A line whose mission number matches a flight that already carries `fdr.ato` from an earlier import
and has a live `MISSION` Strip is an **`UPDATE`**, not a second Strip:

- ATO-owned values (`applyAtoTasking`'s targets) are replaced.
- Seed-owned values (`mission.*`, `identity.flightSize`/`aircraftType`) are replaced **only while
  their provenance is still `'ATO'`**; a value a controller typed (`CONTROLLER_ENTERED`) is kept and
  the preview lists it as `ownedBy: 'CONTROLLER'` (§10.2 rule 3's "stop auto-updating once a
  controller modifies"). For those, `applyAtoTasking` needs the seed-owned paths too — write them
  through the same setter, guarded by provenance; never through `setField` (that would mark them
  `CONTROLLER_ENTERED`).
- A mission in the Board but absent from the new ATO is **listed, never dropped** ("not in this ATO").
- `MSGID` qualifier `CHG` needs no special case: every import diffs.
- For the seed provenance guard to work, **mark seed-derived fields `'ATO'` right after
  `CreateStrip`** (the setter's first call on a new FDR writes provenance for the seed paths too).

### 5.8 The ATO's date vs the mission's date (R2-9, open with the human)

L3 dates every DTG against the ATO's own `TIMEFRAM`; atobrief's `ato_date` is a planner's real-world
calendar date (`ojw1v5.yaml` says 2026-07-04) while the mission clock (H11) may say 2016. Unhandled,
every vul window sits years away from "now" on the scope. You apply the policy in **one** pure helper,
`redateAtoTime(raw, utc, missionNowMs, policy)`, used on every time you store (vul window,
departure/recovery, on-station, ARCT/end-AR windows, targets):

- *default* (R2-9 (a), "the mission's date wins"): keep the DTG's **day-of-month and time**; take month
  and year from the mission clock, choosing the occurrence of that day nearest the mission's now; add
  one document warning `ATO_DATE_DIFFERS` (human-readable: "ATO dated 04 JUL 2026; times placed on the
  mission's calendar, 21 JUN 2016") when `TIMEFRAM`'s date disagrees with the mission date by more
  than a day. A DTG with no day-of-month (bare HHMM) takes the nearest occurrence, as
  `resolveZuluHhmm` does.
- (b) "the ATO's date": store L3's epochs unchanged.
- (c) "time of day only": resolve every time with `resolveZuluHhmm(hhmm, missionNow)`.

Implement all three behind a `policy` argument with (a) as the constant the handler passes, so the
human's answer is a one-line change; record the answer (or the default) in 0071. Re-dated values
replace L3's `…Utc` in what you store; the raw DTGs are stored beside them unchanged.

## 11. Traps

- **T1 — Mode 1/2 stay unwritable by any ATC path.** The tempting shortcut is `WRITABLE_PATHS`;
  that reopens D24. One dedicated setter, called only from the import handler.
- **T2 — The join is not MARSA.** No MARSA store call, no `separationRegime` write, no word "MARSA" on
  the badge. A test asserts both stores untouched.
- **T3 — Per-Facility session binding.** Copy `_handleMutation`'s check, not MARSA's "Primary
  somewhere".
- **T4 — Never trust the client's parse.** The server re-parses; the client sends text + choices.
- **T5 — `createFdr` always mints.** Adoption must release the minted code (`setBeaconAssigned`'s
  reassign path) or the pool leaks one code per imported line. Assert the pool size.
- **T6 — Idempotency is per line.** A derived `clientMutationId` per line, or a reconnect replays N
  Strips.
- **T7 — The shared board in scenario tests.** Absolute counts belong to the whole file; the research
  fixture's lines are imported once per file or each test uses its own fixture copy with changed
  mission numbers.
- **T8 — The 400 ms double-tap guard** (`board-store.js:1287`) if you advance mission lines in tests:
  use `advance()` from `tests/helpers/efsp-scenario.mjs:96`.
- **T9 — Times.** In-game Zulu, resolved against TIMEFRAM first and the mission-clock date second;
  never the wall date (H11, F1 note).
- **T10 — Callsigns over 7 characters** (`LIGHTNING 01`) are normal, not errors: preview row with a
  callsign input. Never invent an abbreviation (D11).
- **T11 — `alertStatus` belongs to L13's Block this wave.** Write it only on a new FDR, only `ALERT`.
- **T12 — Reason codes.** Reuse existing ones (`VALIDATION_ERROR`, `PERMISSION_DENIED`,
  `NOT_HOLDING_POSITION`, `STALE_REV`, `NOT_FOUND`); a new code renders raw in the banner.
- **T13 — "Nothing when nothing is wrong" (ADR 0058) and colour means wrong (ADR 0056).** The AR badge
  is `'on'`, never amber or red; only the Mode 3 conflict is `'attn'`.
- **T14 — The wire carries only what sensors know (ADR 0059).** Nothing you add reads DCS truth; the
  ATO is a document, which is fine, but do not match ATO lines against *tracks*.
- **T15 — A popover or dialog inside Bay content dies on the next delta.** Mount the dialog under the
  panel root.
