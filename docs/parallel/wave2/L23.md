## 5. Design

### 5.1 One capability table for the tactical Positions (H2's "modular")

In `permission.js`, beside the other tables, a **static** table (P5: no config writer; static like
every other grant):

```js
/**
 * H2 / H40 (docs/adr/0080): what each tactical working Position may do BEYOND its op grant.
 * One row per Position, one column per capability, so the next capability (H2: "AIC gets an
 * update in a future version") is a column, not a rewrite. A Position with no row gets the
 * defaults (everything false / 'ALL').
 *
 *  handBackTo      the only Position a line it owns may be transferred to (H2, H40)
 *  tofiAnsweredBy  who answers a TOFI exchange on a line this Position is working (B2: AIC
 *                  "works under TAC_C2's TOFI", guide §4.1 / ADR 0025)
 *  readScope       'ALL' | 'OWNED' — what a session holding only such Positions is sent (B6)
 */
const TACTICAL_CAPABILITIES = {
  AIC:  { handBackTo: ['TAC_C2'], tofiAnsweredBy: 'TAC_C2', readScope: 'ALL' },
  JTAC: { handBackTo: ['TAC_C2'], tofiAnsweredBy: null,     readScope: 'OWNED' },
};
```

with small accessors (`handBackTargetsFor(positionId)`, `tofiAnswererFor(ownerPositionId)`,
`readScopeFor(positionId)`), exported. Tests hold the table: every row's Positions exist in TACTICAL's
config; `readScope` values are in the enum; `handBackTo` targets are Positions of the same Facility.

GCI has no row: it is a TOFI holder with its own grant, like TAC_C2 (ADR 0025).

### 5.7 B6 — a per-session read scope (ADR 0080's main decision)

**Principle.** ADR 0059 says the wire carries only what a session's own sensors know. H40 applies the
same idea to Strips: a JTAC is sent only the Strips it has been handed. Today the whole read path is
unconditional by design (`permission.js` ~182–185's JTAC comment says so), and `snapshotFor()` and
`_snapshotMessage(ctx)` take no session. That changes; the comment is rewritten.

**Scope of a session.** Computed from what it holds, across every Facility (V8):
`readScopeOf(session)` =
- `ALL` if it holds **any** Position whose `readScopeFor` is `'ALL'` (the default for every Position
  without a row), **or holds nothing** (Q6);
- otherwise `OWNED`, with `ownPositions = Map(facilityId → Set(positionId))` of what it holds.

Union semantics: a controller holding JTAC and TAC_C2 sees what TAC_C2 sees. Computed on demand from
the PositionStores (cheap: ≤ 4 Positions × 3 Facilities); no cached state that can go stale.

**What `OWNED` filters** (a new pure module `crc-sync/src/efsp/read-scope.js`, no requires):

| Message / key | `OWNED` session receives |
|---|---|
| snapshot `strips` | Strips whose `ownerPositionId` ∈ `ownPositions[strip.facilityId]` |
| snapshot `fdrs` | FDRs of those Strips only |
| snapshot `correlations` | records whose `fdrId` is visible |
| snapshot `marsa` | relations with a visible participant |
| snapshot `positions`, `bays`, `facilities`, `boardSeqByFacility`, `airspaces`, `fieldStates`, anything L1/L14 added that is not about a flight | unchanged (occupancy, config and airspace are not flights; Q7) |
| `efsp-board-delta` (Mutation broadcast, peer broadcast, NLA-monitor sweep, set-positions re-stamp) | `strips.updated` → visible ones; **every updated Strip that is not visible is added to `strips.gone`** (stateless: a Strip handed back disappears on the next delta; an unknown id in `gone` is a no-op on the client, V9); `fdrs.updated` → visible FDRs; `boardSeq` unchanged. **Always sent, even when empty**, so the client's `boardSeq` stays continuous |
| `efsp-correlation-delta`, `efsp-marsa-delta` | the visible records; skip the message when nothing is left (these carry no Board seq) |
| `efsp-alerts` | conformance and obligations for visible FDRs/Strips only (`stca` is already ATC-only per session) |
| ack of the session's own Mutation | unchanged (it acted on that Strip) — then the broadcast's `gone` removes a Strip it just handed back |
| `efsp-resync` | **always the filtered snapshot** for an `OWNED` session, never a ring delta (the ring replays unfiltered history; a snapshot is the other of §5.6's two paths, so the rule holds). `ALL` sessions: unchanged |
| heartbeat, airspace/field-state deltas | unchanged |

**Wiring.**
- `efsp-ws.js`: `_snapshotMessage(ctx, session = null)` builds as today, then applies
  `readScope.filterSnapshot(msg, scope)` when the scope is `OWNED`; `handleMessage` already has the
  session — pass it to `_handleResync(ctx, session, msg)`. Keep the export name `snapshotMessage`.
- `index.js` facade: `snapshotFor(session)` (argument now used), and a new
  `filterForSession(session, msg)` → the message to send (the **same object** for an `ALL` session —
  the fast path), or `null` to skip. It dispatches on `msg.type`.
- `ws-hub.js`: one private `_broadcastEfsp(msg)` that, for each open session, sends
  `efsp.filterForSession(session, msg)`; stringify once and reuse the string for every session that
  got the same object back. Route through it: `result.broadcast`, `result.peerBroadcast`,
  `result.marsaBroadcast` (and any L1 field-state broadcast — unfiltered, but harmless through it),
  `broadcastEfspBoardDelta`, `broadcastEfspCorrelationDelta`; in `_efspAlertsMsg(session)` apply the
  alert filter; connect sends `snapshotFor(session)`. Non-EFSP broadcasts keep `_broadcast`.
- **A held-set change changes the scope**: after `efsp-set-positions` (ws-hub already calls
  `_refreshCoverage(ws, session)` there), if the scope differs from the one before the message, send
  that session a fresh `snapshotFor(session)` — this is what removes TAC_C2's Strips from a controller
  who gives TAC_C2 up and keeps JTAC, and what fills them in when they take it back.

**Tests** (§6 step 6) cover each row. Performance note for the ADR: at H12's scale (1–4 controllers,
≤ 20 aircraft) the per-session filter is noise; the fast path keeps `ALL` sessions at today's cost.
