## Goal

Make `crc-sync/tests/freeze/` usable by four to eight structural lanes at once. Each lane must be able to prove that its
move is golden-identical, without editing the harness files the other lanes need.

## Owns

`crc-sync/tests/freeze/**` (including `golden/` and a new `selfcheck/` folder), new `crc-sync/tests/clock-policy.test.mjs`,
new `crc-sync/tests/board-seam.test.mjs`, the `freeze:*` lines of `crc-sync/package.json`, `docs/wip/R0.md`.

## Frozen for you

Everything in `crc-sync/src/`, `crc-sync/server.js`, `crc-sync/tools/`, all of `crc-desktop/`.

## Steps

0. **Base check.** merge4's R3-47 server change (an `efsp-resync` reply type) must be committed on your base, and the
   freeze suite must pass there unchanged. If it fails, stop and report: the integrator re-records, not you.
1. **Peer-versus-MARSA order** (S-FREEZE decision). Look for one Mutation that yields both a `peerBroadcast` and a
   `marsaBroadcast`. If you find one, add a hub trace for it. If none is reachable (FREEZE found none in about 4,900
   steps), add `tests/freeze/freeze-hub-order.test.mjs`. It drives `WsHub._onMessage` with a stub `efsp` whose
   `handleMessage` returns all five broadcast keys plus an ack, and asserts one socket receives ack → broadcast → peer
   → MARSA → carrier → SFA. Write it against the wire frames, not the key names, so it survives WIRE's `broadcasts[]`.
2. **Remove `uncarried` from what the hub goldens compare** (FREEZE finding: a soak-host accounting artefact, which APP's
   host rewrite will move). Re-record the hub goldens **once**, in a commit titled
   `test(R0): drop the soak host's uncarried accounting from the hub goldens (approved, plan §3.2)`. The diff must
   remove only `uncarried`. Check that with a key-stripping diff and paste the check into the wip file.
3. **One file per selfcheck mutation.** Move the mutation list out of `freeze-selfcheck.mjs` into
   `tests/freeze/selfcheck/M1.mjs` … `M16.mjs` (and `M5b.mjs`). Each exports `{id, what, file, find, replace, detect,
   also?}`. The runner reads the folder. Add a mutation for step 1's order test (`M17`: swap the peer and MARSA sends).
   `npm run freeze:selfcheck` must report every mutation applied and caught.
4. **Guard 1 (rule wiring)** must keep working once rules are read from collaborators. Scan `src/efsp/board-store.js`
   plus every file under `src/efsp/board/` for both `this._rules.<name>` and a bare `rules.<name>`, with comments
   stripped. Keep the "found at least 40" floor.
5. **Guard 2 (Board surface).** Keep it. Mark `guard-board-surface.json` in the file header comment as a **structure
   fixture** (plan §3.2): lanes update it when they move a private member, and list the change.
6. **The clock policy** (R3-16/S3-3). Replace guard 3 and `guard-wall-clock.json` with `tests/clock-policy.test.mjs`.
   It holds an explicit allow-list of every `Date.now()` and bare `new Date()` site in `src/efsp/**`, as
   `{file, function, clock: 'wall', reason}`, with the reason taken from the code's own comment or ADR 0079's table. It
   fails on a site missing from the list and on a list entry with no site. Retarget M14 to it.
7. **The collaborator seam test** (plan §2.3). Write `tests/board-seam.test.mjs` for `src/efsp/board/**/*.js`.
   (1) It may not `require` `board-store.js` or a sibling under `board/`, except `board/ops/*` requiring `board/strip-util.js`
   and `board/ops/index.js` requiring its op files. (2) It may not read `<expr>._<name>` where `<expr>` is not `this`.
   (3) It may not have a module-level `let`/`var`, or a module-level `const` bound to a `new Map/Set/[]/{}` that is
   mutated. (4) It reads rules only as `this._rules.X` or `rules.X`. The folder does not exist yet, so add a self-test
   that runs the four checks on inline bad and good snippets and proves each one fires.
8. Leave `freeze-tables.test.mjs`'s dispatch scraper alone (WIRE owns it) and the defaults reader alone (DATA-1 owns it).
