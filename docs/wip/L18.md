## Defaults taken (P2)

1. PAR's terminal event reuses the FINAL Role's states: "Landing assured" and "Ball" go to `BALL`,
   "Missed approach" and "Waveoff" go to `BOLTER_WAVEOFF`. No new state (nla.js is L17's). ADR 0064 left this to L18.
2. The cadence bar is a free-running 5 s metronome, not tied to taps (a voice call cannot be observed, a tap
   per call is data entry, which guide 7.10 forbids).
3. Glidepath tolerance 0.3 deg, trend step 0.1 deg, prompt hold 4 s, long-in-pattern 10 min, more than 1 on the
   last leg is advised. All `[SOURCE-DEFINED]`.
4. A leg is a Rack; a Strip whose rack is not a leg shows in an UNPLACED column, never hidden.
5. The pattern board's chip actions are Landed (`RECOVERED`) and Drop (`DROPPED`), per ADR 0064's PATTERN table.
6. Touch alternative to drag: a "Next leg" button on each chip.
7. Mockup was not published as an artifact; it is a file.

## Server half: exact spec (build after L17's Roles merge)

All in `crc-sync/src/efsp/facility-config.js` `DEFAULT_CONFIG` (INCIRLIK) unless noted.

1. `positions: ['OPS','CD','GND','TWR','RSU','APP','SFA','PAR']`.
2. `positionClasses`: RSU, SFA, PAR all `'MILITARY_ATC'`. RSU's "advisory, no separation authority" is expressed
   through `permission.js` rows (as L4 did for PriFly), not a new class: a new class would silently drop STCA
   (ADR 0041 inclusion-list trap).
3. `positionLetters`: RSU `R`, SFA `S`, PAR `P` (the existing O, D, G, T, A stay unique).
4. `coveringChain`: add `SFA: 'APP'`, `PAR: 'APP'`. RSU is deliberately absent so Strips never strand on a
   supervisory Position (PriFly's reasoning).
5. `positionRadars`: RSU `[{kind:'airport',airport:'LTAG'}]`; SFA the same as APP; PAR `[{kind:'approach',airport:'LTAG'}]`.
6. `bays`:
   - `RSU: [{ bayId:'rsu-pattern', rackIds:['closed','initial','base','final'], impliesState:'IN_PATTERN' }]`
   - `SFA: [{ bayId:'sfa-frequencies', rackIds:[one per pool entry], impliesState:'INBOUND'?? }]`: take the
     state the ARRIVAL Strips on an SFA approach carry (verify against `nla.js` ARRIVAL_STATES; do not invent one).
   - `PAR: [{ bayId:'par-final', rackIds:['main'], impliesState:'ON_FINAL' }]`, one Strip at a time (a test
     asserts the Bay refuses a second; same assertion L17 writes for `cv-app*-final`).
7. New config key, validated by `validateConfig`:
   `singleFrequencyApproach: { jurisdiction: 'APP', rotationSize: 3, pool: [{ rackId, mhz }] }` with `pool.length >= 5`
   (guide 4.7), `rotationSize` 3, `jurisdiction` a Position of the Facility, unique rackIds that equal the SFA
   Bay's rackIds. Pool frequencies are `[SOURCE-DEFINED]` placeholders (UHF, 225.000 to 399.975 MHz).
8. Transfer kind `SFA_ROTATION` (trigger type `CONTROLLER_INITIATED`, so the four trigger types stay four),
   APP/SFA to PAR: ownership moves; Role ARRIVAL to FINAL in place, state `ON_FINAL` (as ConvertToArrival, ADR 0023);
   the Strip's frequency Block and its rack do **not** change. A rotation record `{ rackId: positionId }` says
   which Position is currently on each frequency; only the `jurisdiction` Position (APP) may change it, others
   get a `permission.js` refusal. Persist under `state/` (ADR 0048), snapshot key `sfaRotation`, broadcast as
   one delta carrying the whole record (ADR 0064 B6 shape). Audit every rotation.
9. `permission.js` (L17's file, so L18 only after the merge): PAR gets the FINAL-role rows L17 defines for CV_APP;
   RSU gets PATTERN rows (Move between racks, Recovered, Drop) and **no** closure rights (H18: only TWR closes
   or opens a runway; RSU may send `RequestRunway...`, kinds CLOSE, OPEN, BARRIER_CHANGE, per S-L1b).
10. Tests: positions load and validate; every PATTERN/FINAL state pinned to an explicit INELIGIBLE decision for
    the new Bays; guide 4.7 acceptance ("rotation moves the controller, the Strip's frequency is unchanged", D17);
    a non-jurisdiction Position cannot rotate; pool under 5 is rejected; PAR Bay holds one Strip; EEAT set
    before launch survives to the recovery Strip is L17's and is not repeated.
11. Client wiring after that (crc-desktop): a Bay descriptor `view: 'pattern' | 'final' | 'sfa-freqs'` read by
    `bay-view.js` to mount `renderPatternBoard` / `renderFinalPanel` instead of a rack; FINAL's sample comes from the
    correlated track (distance to threshold, altitude, glidepath deviation) and the Strip's runway and decision
    altitude; a Playwright spec on E2E_LANE=9 requiring `./helpers/test` that leaves no Strips on the Board.
