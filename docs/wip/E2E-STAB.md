## What changed

1. **The 400 ms NLA double-tap race.**
   - `crc-sync/src/efsp/board/ops/invoke-nla.js` reads `ctx.wallClock.now()` and `ctx.nlaGuard.ms` instead of `Date.now()` and a literal. `NLA_GUARD_MS = 400` is the shipped value, exported from that file.
   - The clock is injected the way ADR 0096 says: `createEfsp({ wallClock })` -> `BoardStore(..., { wallClock, nlaGuard })` -> `StripOps` (`ctx.wallClock`, `ctx.nlaGuard`) and `BoardPersistence`. `createEfsp` already took `wallClock` (for the undo history); app.js now passes `WALL_CLOCK` through.
   - `nlaGuard` is one `{ ms }` cell shared by every Board of the process. `CRCSYNC_NLA_GUARD_MS` (`nlaGuardFromEnv` in app.js) sets it, **only with `CRCSYNC_TEST_RESET=1`**; anywhere else the shipped 400 stands. `POST /__test/nla-guard {ms}` (src/test-reset.js, same gates as the other hooks) changes it at run time, for the one spec that tests the guard.
   - Other bare `Date.now()` sites injected because they were one hop away on the same classes: `board-store.js` (replay record's `appliedWallAt`), `strip-ops.js` (the drop stamp), `persistence.js` (`droppedWallAtOf`, the replay window in `snapshot()`), and the undo history of a Board built alone. Their five entries came out of `tests/clock-policy.test.mjs`'s allow-list (it asserts every entry has a site). **Not done** (SERVER-SEAMS, phase 3): `index.js:617` (`persistedWallAt`), `correlation-reconciler.js:338`, `archiver.js`/`metrics.js`/`traffic-count.js`/`mutation-log.js` `wallNow = () => Date.now()` defaults.
   - The harness sets `CRCSYNC_NLA_GUARD_MS=0` (in `e2e/helpers/harness-env.js`). **There is also a client-side half**: `bay-view.js`'s `_swallowRepeatAdvance` drops a second advancing press within 400 ms of the first (F-101, board-wide, browser wall time). The eight "sleep 450" specs were therefore also guarding against the *client*; with the server guard at 0 the only race left was that one, and it is not under a load race (both presses are in the same page). `lapseNlaGuard(page)` in `helpers/app.js` installs `page.clock` lazily and `fastForward`s 450 ms, so the 450 ms sleeps are gone without a client change.
   - `e2e/nla-guard.spec.js` is the dedicated spec (see "Defaults taken" for why its window is 1.5 s, not 400 ms). The shipped 400 is asserted by `tests/efsp-board-store.test.mjs` (399 ms later, swallowed, on an injected clock; `nlaGuardFromEnv` gating).
   - Unit tests that slept 410-420 ms now step an injected wall clock: `efsp-board-store`, `efsp-scenario-time-chains`, `efsp-ui-findings`, `undo-scenarios` (and `tests/helpers/efsp-scenario.mjs`'s `advance` for any file that passes a stepped `wallClock`; `steppedWallClock`, `lapseNlaGuard`). **Two files kept their real sleeps**: `efsp-scenarios.test.mjs` and `efsp-scenario-runway-status.test.mjs` (see Findings, freeze goldens).
2. **Per-test Board reset.** `e2e/helpers/test.js`: `resetScope` option, default `'test'` (reset before every test, `force`), `test.use({ resetScope: 'file' })` keeps the old once-per-file reset. `runway-status.spec.js` (serial walk) is the only file flagged. A failed test now clears the marker in the fixture's teardown, so the next test never starts on a dirty Board (that was the cascade). The marker file moved into the run's state dir.
3. **`waitForTimeout`**: 49 at the start (the ticket says 54; 5 had already gone), 1 left. Helpers in `e2e/helpers/app.js`: `settle(page)` (the page's pending-Mutation map is empty, then two animation frames), `frames(page, n)`, `serverTicks(page, n)` (n more `efsp-heartbeat`s on the socket, for "nothing moves by itself"), `lapseNlaGuard(page)`. The two helper sleeps (`expectDoesSomething` 250 ms, `dropStrips` 400 ms) use `settle`. A press that would send something sends it inside the click, so after `settle` "nothing was sent" is a fact. Where the sleep spaced two taps inside the client's window (`l1-nla-clearance-chain`), `frames(page, 4)` gives a page-time gap; `l4-chain` settles between taps and keeps its own page-side gap measurement and retry.
   - **What remains and why**: `signon-reconnect.spec.js` 17 s: the server's 15 s sign-on grace is *its* wall clock and the point of the spec is that it ran out; the sign-off is not visible to the page, so there is no signal. (Making it shorter would need a per-run `sign-on-grace.json`, which the first spec of that file (a 2.5 s blip must stay inside it) forbids.) The short-drop sleep became "the client has been refused once" (counted in the WebSocket shim). `e2e-spec-hygiene.test.mjs` now fails on any other `waitForTimeout`.
   - `update-required.spec.js`: the three negative waits (5 s, 4.5 s, 1.5 s) are `page.clock.runFor(ms)`, which fires every due timer at once, so a reconnect loop would show as a new socket immediately. The suite saved about 9 s of sleeping.
   - `nla-guard.spec.js` has one plain `setTimeout` (real server wall time is its subject).
4. **Assertion timeouts** under 5 s raised to 5000 in every spec and in `helpers/app.js` (about 60 sites). A hygiene test now fails on a new one.
5. **Stable hooks for popover selects**: `data-testid` on the six popover `<select>`s (`marsa-candidate`, `marsa-start-event`, `marsa-end-condition`, `airspace-entry-airspace`, `tofi-counterpart`, `coordination-primitive`; `crc-desktop/app/public/js/panels/efsp/bay/popovers/`), `getByTestId` in the four specs. About 2-3 s. It is **skipped with the reason when `crc-sync/node_modules` is absent** (crc-desktop-release.yml installs only crc-desktop); `crc-sync-docker.yml` installs both and runs it.
7. **Playwright tmp dir** (§5.1): `process.env.E2E_STATE_DIR ??= mkdtemp...` in the config; only the creating process seeds it, a `globalTeardown` removes it (`run-order.js` removes the one it created). Workers and `run-order` children share the runner's dir (this also fixes `run-order`, whose children made a different dir than the servers it had started).

## Defaults taken (P2)

- **Guard in `nla-guard.spec.js` is 1500 ms, not 400.** The second frame is sent when the first one's ack arrives; that round trip measured 329 ms on this machine (load 30-40), so a 400 ms window made the assertion fail for load, the race this lane removes. The spec waits `GUARD_MS + 200` real ms first, because the walk's last press left a latch the guard reads. The 400 itself is a unit-test fact.
- **`resetScope` default is `'test'`**; only `runway-status` is flagged. The other multi-test files (airspace-panel 14 tests, airspace-geometry 14, l2-block-editing 13, l3-coordination 15, mtr-fields 7, ui-a 6, ...) were checked by reading for shared state (module-level `let`s are counters and callsign sequences) and by running the ones I touched; the supervisor's first sharded run is the test of the rest. A file that turns out to depend on its earlier tests needs one line: `test.use({ resetScope: 'file' })`.
- `lapseNlaGuard` uses `page.clock` instead of a client hook (no production change to `bay-view.js`).
- `data-testid`s are production client edits (6 lines in `app/public/js/panels/efsp/bay/popovers/`); no client lane is running in phase 2.

## Findings for other lanes

- **Freeze goldens**: the crc-sync source change is golden-identical (48/48). Converting `efsp-scenarios.test.mjs` and `efsp-scenario-runway-status.test.mjs` to a stepped wall clock **does** change the freeze corpus (`freeze: scenario corpus` fails: `scenario-runway-status` 158 of 194 units differ, `scenarios` 152 of 178; the strip hash `h=` differs from the first InvokeNla on). The corpus replays those files, and their record fields that derive from wall time (the undo window, `invokedAt`) differ when the wall clock steps 410 ms by hand instead of really sleeping. I did not re-record; I reverted those two files to real sleeps. FREEZE-GRAIN should either make the corpus deterministic in the wall clock (inject one in `freeze-world.mjs`) or accept the re-record; after that those two files can step their clock like the other four (`steppedWallClock` is in `tests/helpers/efsp-scenario.mjs`).
- `freeze-guards`' "private members reached from outside the file" golden sees any `_name` shared with another file: a first draft `_wallClock` on `BoardStore` failed it (conformance.js has one). The Board's is `_wallNowFn`.
- **Client double-tap guard** (`bay-view.js _swallowRepeatAdvance`) is browser wall time and board-wide; any spec that presses NLA twice needs `lapseNlaGuard`, whatever the server's guard is. It is invisible to the page (`_lastAdvancingPressAt` is private); a phase-3 client lane could expose a test-only reset or take a clock.
- Transfer-shaped NLAs (`result.transferTo`) never set the server latch (`invoke-nla.js`, `!result.transferTo`): only the client's guard protects a double tap on "Hand Off". Probably intended (the Strip is gone from the pressed Bay); worth a sentence in the briefing.
- The machine ran at load 30-45 during this lane (other lanes' agents), so `e2e` times here (20-50 s per test) are not representative.
- `crc-desktop/e2e/helpers/app.js`'s `seedStrip` and a few `expect.poll`s still carry `{ timeout: 10000 }`; those are above the default and left.
