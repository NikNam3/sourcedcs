# AIRSP-2W: airspace admin and booking tool (sourcedcs-web)

- `routes/bookings.js` (317 lines): resources are `bookingResources.ranges` (id, name, frequency, minAltitude, maxAltitude) and
  `.controllers`; bookings carry `resourceType` 'range' | 'controller', `resourceId`, `altitude` (ranges only). The 999 ft
  rule is `findRangeConflict` (same range, overlapping window, |dAlt| < 999). Range delete cascades its bookings.
  Discord embed is posted on create, a plain line on cancel.
- `public/js/bookings.js` (588 lines): the form picks type then resource from `/api/booking-resources`; the board has two
  sections (ranges, controllers); the admin panel owns range/controller modals.
- There is no `flight-plan-lookup.js` on the web side (it is crc-sync's caller of the web). The web-side token pattern is
  `requireFlightPlanService` in `auth.js` over `checkReleaseUploadToken` (constant-time, empty expected token refuses).
- nginx: `infra/nginx/templates/default.conf.template` (a tracked template since the refactor, not inline in compose);
  the crc-sync vhost proxies `location /` wholesale, so `/api/airspace-registry` would be public without a deny.
  `infra/tests/nginx-render.test.js` compares the template against an old fixture (so the deny edit needs its test updated).
- Tests: `node --test` over `test/`; `store.js` loads `data/` at require time, so route tests monkeypatch `store.saveJSON`
  and mutate `store.state`, never writing files.
- crc-sync's ack shape (`wire/families/airspace.js`): `{airspace, reason, detail, warning, occupied, airspaceSeq}`; the
  registry draft adds `conflicts`. The web passes it through untouched.

## Defaults taken
- DA-3 a, DA-4 a, DA-5 b as settled (booking admins; no map, SVG preview only; one-time migration).
- Legacy range **create** always answers 410 (the briefing says 410 once none remain; a new legacy range could never be
  booked on, since creating a booking on a legacy range is refused). Update and delete answer 410 once none remain.
- Refusing a booking on a legacy range is HTTP 409 with "legacy range: migrate it to an airspace". Existing bookings on
  a legacy range can still be edited or cancelled until migrated.
- Migration deconfliction (999 ft) is judged only between bookings that have not ended: history that overlapped in the
  past is harmless and the admin could not otherwise move it. The altitude-band check covers every booking, past
  included (`allowOutOfBand` is the way through). Idempotency: `bookingResources.migratedRanges[rangeId]` records
  `{airspaceRef, count, at, by}`, so a re-run (even for a range with zero bookings) answers 200 `alreadyMigrated`.
- Airspace booking record: `{resourceType:'airspace', airspaceRef, altitude, ...}` with no `resourceId`; migrated ones
  also carry `migratedFromRangeId`. Editing a booking re-reads the registry (needs crc-sync); cancelling does not.
- crc-sync's answers: 401/403 from crc-sync is reported to the browser as 503 (a service-token problem, never a user
  logout). An ack is relayed with crc-sync's own status when it is 2xx-4xx, and 5xx becomes 502.
- `clientMutationId` is generated by the route (`web-<uuid>`) when the page sends none.
- The theater picker can add a theater name by hand (a theater with no airspaces yet is not in
  `/api/airspace-registry/theaters`); the name is whatever DCS-gRPC `GetTheatre` returns.

## Assumptions about the crc-sync contract (2S-A/2S-B, check at integration)

- `GET /theaters` returns `[{theater,count}]` (a bare array or `{theaters:[...]}` are both read).
- The ack carries `reason` (e.g. `STALE_REV`, `VALIDATION_ERROR`) when refused, plus `detail`, `conflicts:[{field,base,theirs}]`,
  `warning:'AIRSPACE_EDITED_OCCUPIED'` and `occupied` (strings or objects with `callsign`/`stripId`); a delete refusal's
  blockers may arrive as `blockers` or `detail`. The page treats `ack.reason` or `ack.ok === false` as a refusal.
- `EditAirspace` patches carry only changed fields; ROUTE `altLowerFt/altUpperFt` are never sent (derived server side).
  `source` is not sent on create (the server stamps it, `via: 'WEB'`).
- ROUTE bookings use the derived envelope in `altLowerFt/altUpperFt`.

## Human deploy steps

1. Generate `AIRSPACE_SERVICE_TOKEN` (any long random string) and add it to `infra/.env` on the server; add
   `CRCSYNC_SOURCEDCS_WEB_PUBLIC_URL` if sourcedcs.page is not the web's public URL.
2. Deploy: `git pull` + `docker compose up -d` (picks up the compose env lines and the nginx template with the
   `/api/airspace-registry` 404). Until crc-sync ships the registry router (2S-A), the admin page says "crc-sync unreachable".
3. After deploy, open `/airspace-admin.html` and migrate each legacy range (it hides itself when none remain); the
   follow-up chore then removes the legacy tool and routes.
