# L22: STARS scheme for ATC scopes (mockup phase, H49)

The mockup is at `docs/wip/L22-mockup.html`. No product code has been written yet. That waits for the human's approval.

## Defaults taken (P2)

- `SA` fires only on the shared declaration `iffOverride === 'hostile'`, not on bandit. It is a steady yellow `SA` on line 0.
  A primary-only hostile gets a one-line block holding just `SA`.
- `M` is a single letter for every tactical Position (TAC_C2/AIC/GCI) while TOFI is ACTIVE.
- `CST` coast is client-only. It applies to a correlated track during the existing fade window (`fadeGraceMs` + fade, 20 s).
- "ATC map background" off applies only while every Position the user holds is ATC. A mixed session keeps the basemap.
- Line 0 stacks its indicators by severity: EM/RF/HJ, then CA, then SA, then the conformance tag.
- Clicking the target acknowledges or cycles FDB↔PDB. Clicking the block opens the track panel, and dragging it moves it, as today.
- Provisional correlation keeps the `?` in v1 and does not use the STARS code pair.

## Findings

- MapTiler's glyph endpoint (`crc-desktop-scope-style.json`) serves `Roboto Mono Regular` and `Roboto Mono Medium`. I checked against
  the fallback: an unknown font name returns Noto Sans, while these names return their own font.
- Every client already receives the whole EFSP Board (`efsp-ws.js`: "the client filters by what it holds"), so an APP-only
  scope can derive H48's `M` from the TOFI coordination or mission line with no wire change.
- The only new wire field is `scheme` on the track (`presentation.js` `WIRE_KEYS`, plus the wire-strictness test). Owner
  letters are new facility config.
