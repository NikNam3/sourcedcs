The advisory is a grey note at the top of ▼, never on the collapsed face, never an amber ▲ reason line or an indicator: a flight on an MTR with working radios is not wrong (ADR 0058, "nothing when nothing is wrong"). It states the §9.4 rule, shows the half we have (the ACTIVE ALT clearance, FL180 here), and says the other half — minimum IFR altitude per segment — is not in the system. It never computes a "lost-comms altitude" and never uses EXIT ALT (that is the pilot's request, not a clearance). With no ALT posted it reads "…the altitude in the last clearance: none posted (ALT is empty)."

Any Position not listed (and every Position, for Blocks not on its face) reaches all six in ▼. All six are ordinary click-to-edit cells: fixes/designator are free text (upper-cased, no format rule — there is no route table yet, H23); times are 4-digit UTC HHMM (14:32Z → 1432; 2460 refused at the cell); EXIT ALT takes FL210 / 080 / 8000. Overwrites keep no history (H25 — gap recorded for all fdr Blocks).

Design choices in one list

  • Conditional row: the MTR group is drawn only when any of the six MTR fields has a value — no Strip pays height for an MTR it does not fly.
  • Own row at column 1, M11 first: MTR · EXIT · EXIT EST · EXIT ALT, then ENTRY · ENTRY TM. Same x on every MTR Strip in a Bay.
  • No colour, no badge: prominence is placement and grouping only (colour = something is wrong).
  • Lost-comms advisory: grey note at the top of ▼ + tooltip on the EXIT ALT label. States the rule, shows the ACTIVE ALT clearance, says MIA data is unavailable. Never on the collapsed face.
  • Clearing MTR does not clear the others (no hidden writes); the group stays until all six are empty.
