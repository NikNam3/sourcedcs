## How a later lane retargets a mutation

Mutations are one file each in `tests/freeze/selfcheck/`. A lane that moves code a mutation targets edits only that file: `file` (the new path), `find` and `replace` (strings that match exactly once in it; `also` is a
second edit in the same file) and, if the detector moved, `detect` (names are the failing test file without `.test.mjs`: `freeze-hub`, `freeze-guards`, `clock-policy`, `board-seam` ...). Prove it with
`npm run freeze:selfcheck M<n>` (one mutation, about 20 s plus the baseline) and run the whole `npm run freeze:selfcheck` once at the end of the lane. The runner reports "MUTATION DID NOT APPLY" when a find string no longer matches exactly once.
Clock sites: edit the `file`/`function` of the entry in `WALL_ALLOW_LIST`, keep the reason. Board surface: `UPDATE_GOLDEN=1 node --test tests/freeze/freeze-guards.test.mjs` and list the change in the commit.
