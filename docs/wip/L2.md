## Defaults taken

- **Supervisor correction (overrides briefing §5.3 / Q2):** MTR times (`entryTimeUtc`,
  `exitEstimateUtc`) are stored as **epoch ms**, not `HHMM` strings. A typed `HHMM` / `HH:MM` /
  `…Z` is dated by the **mission clock** (`FdrStore`'s injected clock, H11), never the wall clock,
  and displayed as `HHMM`.
- No existing "typed HHMM → epoch" helper existed, so a new pure module was written for reuse:
  `crc-sync/src/efsp/zulu-time.js` — `parseZuluHhmm`, `resolveZuluHhmm(text, nowMs)`,
  `formatZuluHhmm(ms)`. **Which day:** the occurrence nearest the mission's now (±12 h), so
  `0010` typed at `2350Z` is tomorrow, not 23 h ago. `[SOURCE-DEFINED]`; L16 (§10.5 times) should
  reuse it for the other typed time Blocks (the Q43 / T9 bug).
- A finite number written to an MTR time is taken as epoch ms already (imports, scenarios).
- Q6: block altitudes (`FL190B210`) refused; single altitude only.
- Q8: designator/fixes trimmed and upper-cased, no format rule (D11, H23 free text).
