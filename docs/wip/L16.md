## What changed

- **Block `9F` is a picker.** Its options are the route list from the last fetch that succeeded (`efsp-stereo-routes.js` `cachedStereoRoutesClient()`), in table order. The flight's current route is added when it has been retired. With no table and no stereo on the flight, the cell is plain text titled *"no stereo routes configured"*. With no table and a stereo on the flight, the picker offers that route and "—". "—" sends `''`, which clears the label and keeps the route. The server path is unchanged.
- **§10.5 chains**, computed at read by `time-chains.js`. There are two byte-identical copies, one per package, held equal by `crc-sync/tests/fixtures/time-chains.json` plus a byte-equality test on each side.
  - departure (6): CONTROLLER > FLIGHT_PLAN > ATO
  - off-block (17): CONTROLLER > EST_DEPARTURE
  - takeoff (18): CONTROLLER > EST_OFF_BLOCK
- **The new stored input:** the DD-1801's `depTime` → `toFdrFiledSeed.flightPlanDepartureTimeHhmm` → `createFdr` → `fdr.timeInputs.flightPlanDepartureUtc`, dated by the mission clock. `restore()` seeds `timeInputs` onto older FDRs.
- **Display.** `ZULU_HHMM_BLOCKS` now also covers `M6`/`M7`. The set is derived from the Block Maps by a test. For Blocks 6/17/18 on a DEPARTURE, the value comes from the chain. An estimate is shown in italics (`.efsp-block-estimated`). The source is on hover, both on the value cell and on the ▼ row's label.
- **M6/M7 typed times (S-F4).** `mission.vulWindowStartUtc`/`EndUtc` are in `TYPED_TIME_LABELS`. The end resolves to the first occurrence after the start (`resolveZuluHhmmAfter`). This applies in `setField` and in `createFdr`.
- **Strips rebuild when the stereo list lands.** Found while testing, see Findings.

## What the usage guide should say

- **Picking a stereo route on a live Strip.** Click STEREO (Block 9F) and choose from the list. Choosing a route re-files the flight: the route, requested altitude and airports come from the table. "—" cancels the stereo label and keeps the route. To file a different route, edit RTE (Block 9); editing RTE also removes the stereo label by itself. A route the squadron has retired stays on a flight already filed with it. If no routes are configured, STEREO is plain text and says so on hover.
- **What an italic time means.** TAXI (17) and TAKEOFF (18) show an estimate in italics until a controller enters the actual time: the P-time for TAXI, and the off-block time for TAKEOFF. Type the actual time over it (`1432`) to replace it. Clear your entry to get the estimate back. P-time (6) is never italic. If no controller has entered it, it comes from the filed DD-1801 (item 13) or, failing that, from the ATO.
- **Reading the source on hover.** Hover the value, or the label in ▼. The hover shows where the time came from, for example *"~1430Z estimate: P-time, from the filed DD-1801 (item 13, EOBT)"*. When a controller has entered the time, it also shows what you would get back if you cleared it.
- **Vul window.** VUL STRT and VUL END are typed as `HHMM`. The end is always after the start, so `2200`–`0130` runs overnight.

## Pilot walk (step 9)

Walked through the Playwright spec (`e2e/l16-picker-and-times.spec.js`) and the scenario (`crc-sync/tests/efsp-scenario-time-chains.test.mjs`). Screenshots are in `docs/wip/L16/`. Five requests, five findings.

1. **"VIPER11, request PACK 2."** Click STEREO and pick PACK2. The picker opens focused, the pick commits, and RTE and CRUS ALT change on screen. That is one gesture, where before there was a name to spell. *Felt fine.* On OPS and CD, `9F` is on the face; at GND/TWR/APP it is only in ▼.
2. **"Cancel the stereo, we'll file full route."** "—" clears the label and the route stays. The controller then edits RTE. **Finding W1:** the "—" step is redundant. Editing RTE clears the label by itself (0050), so the guide should say "just edit RTE". "—" is only for "keep this route but it is not PACK 2 any more".
3. **"Off-block time 1425."** TAXI is on **no Position's face**, so GND has to open ▼ to type it. Once typed, the italics go, TAKEOFF follows at `~1425`, and the hover reads "entered by a controller / if cleared: estimate: P-time, …". **Finding W2** (owner: the field lists, 0056/L13): a GND controller receiving the call has to expand the Strip. Consider TAXI on GND's face.
4. **"We're delayed, new P-time 1450."** P-time is on OPS's face only. The TAXI and TAKEOFF estimates move to `1450`. **Finding W3:** a TAXI a controller already typed (1425) does **not** move, because a controller entry stops the chain (§10.2 rule 3). The Strip then shows TAXI 1425 before a P-time of 1450, and nothing flags it. That is correct by the rule, but a conformance-style hint may be wanted. Owner: whoever takes §10.2 next; not this lane.
5. **"The stereo list changed on the server."** It can only change by restart (P5). After reconnecting, the snapshot re-fetch refills the cache. **Finding W4, fixed here:** the first render after a load or restart always beat the fetch, so every Strip's `9F` stayed "no stereo routes configured" until its FDR next changed. The cache key is now in the render signature, and a changed cache asks for a render. Covered by a DOM test and by a reload step in the e2e spec.

**Also found:** typing the same `HHMM` that an estimate shows, to "confirm it as the actual", sends nothing, because the cell treats an unchanged value as a no-op edit. **Finding W5:** a controller cannot accept an estimate as the actual without retyping a different value. Recorded in 0073's *Left open*.
