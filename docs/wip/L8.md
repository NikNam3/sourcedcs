### B1 — a JTAC handed a mission line can never hand it back (stranding)
- Reframed by **H40**: TAC_C2 → JTAC transfer-in is *correct*; the missing half is transfer-back.
- Severity: stranding.
- Repro: TAC_C2 `CreateStrip MISSION` in `tac-c2-tasked`, jumped to ON_STATION → TAC_C2
  `TransferStrip {toPositionId:'JTAC', bayId:'jtac-mission'}` → ok, owner JTAC → JTAC
  `TransferStrip {toPositionId:'TAC_C2', bayId:'tac-c2-on-station'}`.
- Observed: JTAC transfer-back `ok:false, reason:PERMISSION_DENIED` (no detail). TAC_C2 `SetBlock`
  and `TransferStrip` on it → `NOT_OWNER` (no detail). JTAC vacates →
  `[{positionId:'JTAC', count:1, routedTo:null}]`, still owned by JTAC. No op but a vacate
  warning ever reaches the line again.
- Expected: H40 — "same transfer-in / transfer-back model as the AIC (H2)". JTAC may
  `TransferStrip` a line it owns back to TAC_C2 and nothing else (the fix is a grant narrower than
  `NON_CREATE_OPS`; H2 asks for it to be modular). Also worth a covering-chain entry
  `JTAC: 'TAC_C2'` so a JTAC walking away does not strand the line.
- Where: `crc-sync/src/efsp/permission.js:186` (`JTAC: new Set([])`); `board-store.js:988`.
- Pinned by: `crc-sync/tests/efsp-scenario-tactical.test.mjs` — "SCENARIO J2 TAC_C2 hands a line to JTAC and JTAC hands it back (H40)"
  (`todo: 'L8 B1'`).

### B7 — AIC advances a mission line through the SetState escape hatch (new; was briefing O1)
- Severity: doctrinal (**H2**: AIC "never advances state; transfers back to TAC_C2 to go
  OFF_STATION").
- Repro: `toAic(taskedLine('AIC14'))` → AIC `SetState {toState:'OFF_STATION'}` → `ok:true`.
- A second defect shows in the same ack: the Strip is now `state:'OFF_STATION'` but still in
  `bayId:'aic-on-station'`, a Bay that **implies ON_STATION**. `_relocateForImpliedState` looks
  only in the owner's Bays (`board-store.js:1093-1100`), and AIC has no OFF_STATION Bay, so
  nothing moves it. The Board now holds a Strip whose Bay contradicts its state.
- Expected: refused, `PERMISSION_DENIED`, as InvokeNla already is (A1). ADR 0027:55 makes
  `SetState` the unchecked escape hatch for every Position. That is reasonable for a Position that
  owns some state transitions. AIC owns none (`MISSION_STATE_OWNERS`, `permission.js:376`). So
  either AIC loses `SetState` (and `Undo` of a state change) from its grant, or `SetState` is
  checked against the state owners for MISSION. Supervisor's call.
- Where: `permission.js:181` (`AIC: new Set(NON_CREATE_OPS)`), `board-store.js:1102`.
- Pinned by: "SCENARIO A7 AIC cannot move a line past its state with the SetState escape hatch (H2)"
  (`todo: 'L8 B7'`).

## For the usage guide / briefing (the integrator folds these in)
- The AIC workflow as the server enforces it (H2), walked end to end in A1. TAC_C2 transfers the
  line to `aic-on-station` at check-in, and the transfer is legal only if the line is already
  ON_STATION. AIC may annotate (M2, flags) and move the line between On Station and Committed. It
  cannot advance state; the NLA shows "ON_STATION is not AIC's to advance". It hands the line back
  to `tac-c2-on-station`, and TAC_C2 takes it OFF_STATION.
- While AIC holds a line, TAC_C2 cannot touch it, and that includes answering CTR's TOFI EXIT (B2).
- The shared DOM stub (`crc-desktop/tests/helpers/dom-stub.js`) now has three users. A harness that
  needs `focus()` to move focus overrides it per element, as the reachability harness does. The
  helper stays as it is.
- To read a client module's top-level `const` in a test, evaluate its name in the vm context
  (`vm.runInContext('NAME', ctx)`) and copy the result out of the context's realm before
  `assert.deepEqual`.
