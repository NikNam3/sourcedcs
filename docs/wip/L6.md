# L6 — WP8 soak harness (lane report)

Branch `lane/L6-soak`, cut from `efsp-wp5-correlation` at `cfcf344`. Owns `crc-sync/tools/soak/**` and
`.github/workflows/crc-sync-soak.yml` (H37). No production file was edited; `npm test` in crc-sync is
**1171/1171** before and after (the briefing's 1151 predates F1).

**The harness works; the soak FAILS, with evidence** — as the briefing predicted. Dropped Mutations in
the strict ledger sense (lost acks, audit gaps, missing broadcasts, internal errors) are **zero** in
every run. What fails is: H1 (rebalance side effects never broadcast), H4 (resync across a restart),
retained-record memory growth (H3, expected until H36/L24), and — informationally — H5 and H8.

## 4. Findings

Evidence format: seed + command, report excerpt, suspected file:line, severity, suggested owner. Every
command is from `crc-sync/`, commit `37682e2` or later on this branch.

**F1 — H1 CONFIRMED: a rebalance changes other Strips' `orderKey` and `rev`, and no client is told.**
`node tools/soak/run.js --minutes 240 --seed 1`: `rebalances 13 / exhausted throws 13`, 48 Strips
rebalanced, `silentStaleness 127 {REBALANCE_SIDE_EFFECT:127}`, staleness persisting up to **1320 s**
(22 min) on continuously connected clients. Stress 60: 23 rebalances, `silentStaleness 32`.
`board-store.js:217-225` (`_rebalanceRack` bumps rev + `_touch` on every Strip in the Rack) vs
`efsp-ws.js:190-199` (the broadcast carries only `result.strip`). Consequences seen: later `STALE_REV`
refusals on those Strips, and — worse — **resync cannot heal it**: the triggering Mutation's broadcast
advertises a `boardSeq` that already covers the rebalance touches, so a client resyncing from that seq
gets an empty delta and stays stale (stress 60: `resyncDivergence 1`, causes `{REBALANCE_SIDE_EFFECT:3}`,
`lastSeq 84 == currentSeqAtResync 84`). Severity **high** (guide §5.4 "one Board event"; WP8 "no
dropped Mutations"). Owner: wave-2 bugfix (return the rebalanced Strips on the result and broadcast
them; the host's `uncarried` list is a ready-made test oracle).

**F2 — H4 CONFIRMED: `efsp-resync` across a restart answers from the wrong lifetime.**
Every run with a restart: e.g. default 10 m `acrossRestartDivergence 1`
(`INCIRLIK, path delta, lastSeq 2, currentSeqAtResync 12, missing 2`); 240 m: 3 (one per Facility).
`restore()` does not restore `_seq` (`board-store.js:2397-2411`, on purpose), and the `rewound` guard
(`efsp-ws.js:272-273`) only catches `lastSeq > currentSeq`; once the new lifetime's seq overtakes the
client's, a delta from the new ring is served as if continuous — Strips dropped before the restart
stay on the client ("extra"), Strips created are missed. Latent today because the shipped client never
sends `efsp-resync` (briefing §3.10), live the moment it does. Severity **high** (latent). Owner:
integrator / wave-2 (a Board epoch in snapshot + resync).

**F3 — H3 CONFIRMED (expected, H36): retention drives heap, snapshot size, `_persist` cost and latency.**
240 m: `strips.dropped 19 → 378` (101/h), `fdrs 19 → 183`, snapshot 23 KB → 470 KB, board file written
1.75 GB in total, latency p50 0.8 → 13 ms. `--prune-retired`: snapshot 57 KB at the end, p50 1.7 ms,
196 MB written. Heap slope 0.77 MB/h (R² 0.93) is under the 1 MB/h threshold, but net growth **+20%**
fails. Per-DROPPED-Strip heap ≈ **7.8 KB**. Not a harness bug (S-R2-6); scheduled as L24.

**F4 — NEW: the idempotency cache and the resync ring are the rest of the growth, and they pin
retired records.** With `--prune-retired` the heap still grows 0.74 MB/h (+20%, R² 0.93), and the only
structures still rising are `_appliedMutations` (→ 1218 of 5000 at INCIRLIK in 4 h) and `_log`
(→ 1280, pruned at 2000). Both are bounded, so this plateaus — but only after ~16 h of realistic
traffic for the 5000 cap. `_appliedMutations` stores whole result objects holding **live references**
to Strips and FDRs (`board-store.js:244-271`, results return the live `strip`), so **L24's archiving
will not free a Strip or FDR that is still in the last 5000 results**. Severity medium. Owner: L24 (H36).

**F5 — H5 CONFIRMED / R2 (reported, not gated): a CreateStrip whose ack died with the process is
created twice on retry.** Every run: `R2 CreateStrip:appliedTwice` (audit lines 1 before replay, 2 after,
the restored Board had it). `restore()` drops `_appliedMutations` (`board-store.js:2397`). The other R2
mode (stress, restart 2): `SetFlag: lost` — the audit line was written, the snapshot write was not
(crash between `mutationLog.record` inside `applyMutation` and `persist()` at `efsp-ws.js:163`); the
retry then applied it, leaving **two audit lines for one effective change**. Severity medium
(documented Phase-1 gap). Owner: supervisor decision (§10 Q1/Q11).

**F6 — H8 CONFIRMED: lowest-free code reuse binds a new flight to the previous flight's still-airborne
aircraft.** 240 m: `misbinding 46 {LINGERING_TRACK:46}`; stress 60: 84. Example: FDR `f23f0da3…` CORRELATED
`matchedBy BEACON` to track `16777303`, which belongs to the previous FDR on code `0011`.
`code-allocator.js:67-76` (`allocate()` returns the lowest free code) with a 2–5 min linger. Severity
high for correlation (§6.6 D1 class). Owner: wave-2 (a quarantine on released codes, or LRU allocation).

**F7 — H6 CONFIRMED:** `_nlaHistory` holds NLA-dropped Strips: 240 m `nlaHistory 99, of which DROPPED 94`
(`board-store.js:1345` sets it on the terminal Drop; only transfer/Undo delete it). Small (bounded by
drops, 30 s semantic life). Owner: L24 alongside archiving.

**F8 — H2: mechanism CONFIRMED by the probe, NOT reached in traffic.** Keys grow without bound under
repeated same-slot inserts (183 chars at 400 pairs, no rebalance — `needsRebalance` is never called,
`order-key.js:160-163`). In traffic the exhaustion-triggered rebalance fires first (stress: 23 throws,
max key 26; realistic 240: 13 throws, max key 7), so the 40-char threshold was never crossed and
**no `ORDER_KEY_EXHAUSTED` escaped** (`internalErrors 0`). The price of relying on the throw is F1.
Severity low on its own. Owner: whoever fixes F1 (a proactive rebalance would make F1 rarer, not fix it).

**F9 — H7 not reached:** max `_cidSeq` 230 in 4 h realistic, 354 in 1 h stress per Board lifetime →
a stress-rate session passes 999 after ~3 h. Low. Owner: integrator.

**F10 — NEW: a covering Position is handed Strips it may not advance, and nothing hands them back.**
When CD is vacated (manning churn), CD-bound Strips are routed to GND via the covering chain
(`facility-config.js:93`, `board-store.js:1007-1012`), where every NLA is refused
`PERMISSION_DENIED "PENDING_CLEARANCE is not GND's to advance"` (`board-store.js:1157`). Retaking CD
does not return them. 240 m: 149 such refusals; the harness now models the controller dragging the
Strip back (`TransferStrip` to CD) once CD is manned. Severity medium (briefing-habits "the facility
changing underneath a flight"). Owner: L1 / wave-2 bugfix.

**F11 — NEW: replaying a refused Mutation returns the cached, older Strip.** A replay of a `STALE_REV`
refusal answers from `_appliedMutations` (`board-store.js:246`) with `deepClone(strip)` as it was at the
original refusal; the shipped client applies an ack's Strip on refusal (`efsp-state.js:247`), so its
replica goes **backwards** (seen: rev 5 → 4 in a stress run during development; 0 in the four record
runs). Counted as `replayStaleAck` (warning). Low. Owner: integrator.

**F12 — NEW: airspace audit lines carry no `clientMutationId`.** `efsp-ws.js:332-335` does not pass
`msg.clientMutationId` to `airspaceStore.apply`, so `airspace-store.js:109-110` logs `undefined`. The
ledger reconciles airspace in aggregate (`airspaceAudit.storeAnswers == logLinesWithoutCmid`, 3 == 3 in
stress) instead of per message. Low. Owner: integrator (one-line).

**F13 — NEW: correlation, airspace and MARSA ops are not idempotent by `clientMutationId`.** Only
`BoardStore` has an applied-Mutations cache; a retried correlation/airspace/MARSA message is applied
again (or refused `STALE_REV`) and audited again. The harness replays all four kinds and reports
non-Board replays as warnings (`replayNotIdempotent.byKind`, `replayAuditLines`); none misbehaved in
these seeds because replays went through a rev check. Low. Owner: integrator.

**F14 — briefing correction: an OVERFLIGHT can never propose coordination.** `coordination.js:65`
allows proposals only from ARRIVAL/INBOUND and DEPARTURE/HANDED_OFF, so the briefing's overflight
POINT_OUT/TRAFFIC leg is impossible. That leg moved to a CTR-originated INBOUND arrival
(`popupArrival`'s "proper" half), which POINT_OUTs / calls TRAFFIC to APP before handing off.

Confirmed-clean in every run: `lost 0, duplicateAck 0, auditMissing/Duplicate/ForRefusal/Orphan 0,
internalErrors 0, broadcastMissing 0, boardLostOnRestart 0, replayNotIdempotent 0, orphans 0`.
Correlation rate mean 0.79 (240 m), 0.45 (stress — solo crew, more faults per airborne minute).

## 5. Defaults taken (P2)

1. **Crews and profiles per H46 + S-R2-6**, replacing the briefing's 9-session default: `three` for
   realistic, `solo` for stress, `full` kept. Spawns are held at a *concurrency* target (12 / 36 / 10)
   rather than an hourly rate. SOURCE assumption, not a measured figure.
2. **A passive `probe-h4` client** in every crew (never declares Positions, never sends) for the H4 probe
   and as a pure shadow; it is not counted as a controller session.
3. **`crypto.randomUUID` is seeded in the host** (per lifetime), overriding D5: `getRack`'s stripId
   tie-break otherwise made stress runs irreproducible (found by `SOAK_DIGEST_TRACE`). Stated in the report header.
4. **Warm-up** = max(10% of run, min(20 min, 25% of run)), not "max(20 min, 10%)": the briefing's rule
   swallows any run ≤ 20 min, including the selfcheck's. Sampling is denser for short runs
   (light = run/40 clamped to 10–60 s, heavy ≤ 5× light).
5. **The heap fit uses one host lifetime** (the one with the most post-warm-up samples): a restart is a
   new process and a new heap. The selfcheck leak is re-armed in the new process.
6. **R2 is made deterministic**: mode A kills the host after the Mutation applied and persisted but
   before the ack (`dieAfter`); mode B arms a crash inside `_persist`'s snapshot write (audited, not
   persisted). Alternates CreateStrip / Strip op per restart. Reported, not gated (§10 Q11).
7. **H4 and resyncDivergence FAIL**; R2 does not (§10 Q11 default). Non-Board replay idempotency and
   `replayStaleAck` are warnings; Board replay idempotency gates.
8. **`--direct` is not implemented** (the WsHub transport worked throughout; the flag errors out
   rather than silently doing something else). Wire mode (spawning `server.js`) deferred per §10 Q9.
9. **MARSA traffic not generated** (optional for v1). The MARSA broadcast/audit paths are covered by the
   ledger if anything emits them.
10. **Covering-Position hand-back** (F10) is modelled as the controller's manual fix, so flights do
    not stall forever; the refusals are still counted.
11. **Retention by design counts as memory growth** in the verdict (§10 Q1); `perDroppedStripKB`,
    `residualSlopeMBPerHour` and the `--prune-retired` run give the attribution.
12. **Known gap: the resync *snapshot* path is rarely reached.** No record run's outage exceeded the
    900-seq window (outages are 70% 5–90 s, 30% 5–25 min), so `resync.snapshot` is 0 in all four and the
    verdict warns. Development stress runs hit it 1–2 times. A dedicated "long outage" event, or a
    smaller ring in a debug build, would force it; not done.
13. Obligation alerts: both shapes supported (pre-L7 one-shot `onAlert`, post-L7 state in `efsp-alerts`
    via `getAll()` / `setOnEfspChange`), gate nothing (T11). This branch is pre-L7.
