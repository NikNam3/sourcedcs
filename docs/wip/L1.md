## What changed

- **New files:** `crc-sync/src/efsp/field-state.js` (pure) and `field-state-store.js` (`FieldStateStore`, the sixth store), plus the two new test files above.
- **The field-state model:** one runway record per pavement (`05/23`, ends `05`/`23`), with the active **end** held on the Facility record.
- **Who does what:**
  - TWR closes, opens and begins a barrier change.
  - Everyone else sends `RequestRunwayStatus`, and TWR accepts or rejects it.
  - OPS completes the barrier change and signs off the inspection, which is the only way back to OPEN.
  - The runway-change machine carries OPS/APP acknowledgements, a one-input self-coordinated variant, and the skipping of unmanned acknowledgers.
- **The inhibits (rule 1)** apply on the NLA button, the drag, the advisory `nla` stamp and `SetState`.
- **Placement:** every non-drag placement files a Strip into the runway-queue rack by runway.
- **On the wire:** `efsp-field-state-mutation` / `-ack` / `-delta`, and `fieldStates` in the snapshot. Field state is persisted and survives a restart intact.
- **Active runway:** derived from the mission wind at load, once per mission.

## What the usage guide should say

**The runway (field state).** Incirlik's runway 05/23 is one pavement with two directions. The field-state board shows:

- its status: OPEN, CLOSED, SUSPENDED (works / barrier change) or SUSPENDED (awaiting inspection);
- which end is active;
- any runway change in progress;
- any request waiting on tower.

**Tower owns the runway.**

- Only TWR closes it, reopens it, or takes it out for a barrier change.
- OPS, CD, GND and APP *ask* tower: "request close", "request open" or "request barrier change", with an optional note. Tower accepts, which carries it out and records who asked, or rejects.

**A barrier change.**

1. TWR suspends the runway (usually at OPS's request). Both directions are suspended together.
2. When the work is done, OPS marks it complete. The runway is still suspended, now "awaiting inspection".
3. Only OPS can sign off the inspection, and that is what reopens the runway. Tower cannot simply reopen a suspended runway, and nobody can close it to get around the inspection.
4. The inspection records who signed it off, at which Position, and when.

**While a runway is suspended or closed:**

- Every departure queued for it, lined up on it, or taxiing towards it is held: its NLA button shows the reason and refuses. So does dragging it into the runway queue.
- Every arrival handed to tower for it is held short of FINAL.
- The reason names the runway and the cause, e.g. `runway 05/23 suspended — barrier change`.
- An aircraft already on FINAL can always be marked LANDED, because touchdown is not a clearance.
- Moving a queued Strip to the other direction's rack does not release it at Incirlik, because both racks are the same pavement.

**Which runway a Strip is judged against**, in order:

1. the runway rack it sits in (or is being dropped into);
2. the runway filed on the flight plan (8A for a departure, 8B for an arrival);
3. the active runway.

A Strip that resolves to none of these is never held.

**Changing the active runway.**

1. TWR proposes the new end.
2. OPS and APP each acknowledge, in any order. Either may reject, and TWR may withdraw until it begins.
3. TWR can begin the change only once both have acknowledged. An acknowledger that nobody holds when the change is proposed is skipped and recorded. A controller holding TWR, OPS and APP alone does it in one action ("self-coordinated runway change").
4. When TWR completes the change, the active end switches and the runway waits for OPS's inspection like any suspension; its traffic is held until then.
5. After the inspection, departures sent to the queue by NLA go to the new end's rack. Strips already queued for the old end are not moved.

**At mission start** the active runway is the end most into the mission's wind. A reconnect or a crc-sync restart keeps whatever tower has chosen since.

*"What is ours":* tower's sole authority, CLOSED holding traffic, the request/accept flow, the true-heading wind rule, and the acknowledger skip are SOURCE practice.

## What the briefing should say (§3-style handoff paragraph)

**Field state (§9.7, ADR 0061) is the sixth store.**

- **Store:** `FieldStateStore` has one instance and one record per Facility with a `fieldState` inventory (INCIRLIK only). Each record has its own `rev` and the store has its own sequence (`fieldStateSeq`); every op is audited (refusals and `STALE_REV` included) under `fieldStateFacilityId`.
- **Config vs state:** the inventory (runways as pavements with `ends`, `endHeadingsTrue`, `rackIds` per end, `arrestingGear`, acknowledgers, inspection authority, pads, `airportIcao`) is `DEFAULT_CONFIG`, read once at startup and never written. Status, suspension, closure, inspection, requests, `activeRunway` and `runwayChange` are store state only.
- **Pure rules:** `field-state.js` holds the status machine (the absent `SUSPENDED_BARRIER_CHANGE → OPEN` edge *is* rule 2), runway resolution, the inhibit wording, the into-wind end, `runwayAdvisoryFor` and `runwayRackFor`.
- **NLA:** `nla.js` reads `ctx.fieldStateFor()`, which defaults to null and fails open. `board-store.js` threads it through `_nlaCtx`, adds the drag target rack, files Strips by runway through `_placementRack`, and refuses `SetState` into a runway-using state on an unusable runway.
- **Rule 5 deviation:** field state has its own delta and sequence, **not** the Board sequence.

Traps:

- The 400 ms double tap swallows a second NLA press.
- Every scenario file needs its own durable board.
- The session binding is per-Facility, not "Primary somewhere".
- Never add field-state kinds to `OP_KINDS`.
- `FINAL → LANDED` is never inhibited.

**My own choices:**

- Ties in the wind (a pure crosswind) go to the first end in inventory order (05).
- `RequestRunwayStatus` is open to OPS, CD, GND and APP (not CTR, not MRUs).
- A request made moot by a direct tower op is settled in that op's transition.
- A proposal naming a closed target runway is refused.
- `CompleteRunwayChange` over a pavement already `SUSPENDED_INSPECTION` (barrier work awaiting inspection) keeps the barrier suspension, and one inspection covers both.

## Wire contract for L1b

**Inbound**

```js
{ version: 1, type: 'efsp-field-state-mutation', clientMutationId, facilityId /* default INCIRLIK */,
  baseRev /* record rev; omit to skip the check */, actingPositionId,
  op: { kind, runwayId?, toRunwayId?, action? /* CLOSE|OPEN|BARRIER_CHANGE */, note?, reason? } }
```

`kind` is one of:

- `CloseRunway{runwayId, reason?}`
- `OpenRunway{runwayId}`
- `BeginBarrierChange{runwayId, note?}`
- `CompleteBarrierChange{runwayId}`
- `CompleteInspection{runwayId, note?}`
- `RequestRunwayStatus{runwayId, action, note?}`
- `AcceptRunwayRequest{runwayId}`
- `RejectRunwayRequest{runwayId, note?}`
- `ProposeRunwayChange{toRunwayId /* an END, e.g. '23' */, note?}`
- `SelfCoordinateRunwayChange{toRunwayId, note?}`
- `AckRunwayChange`
- `RejectRunwayChange{note?}`
- `WithdrawRunwayChange{note?}`
- `BeginRunwayChange`
- `CompleteRunwayChange`

`runwayId` is the pavement id (`'05/23'`).

**Ack (sender only)**

```js
{ version: 1, type: 'efsp-field-state-ack', clientMutationId, facilityId, runwayId,
  ok, fieldState /* always the current record */, reason?, detail?, fieldStateSeq }
```

`reason` is one of `VALIDATION_ERROR`, `PERMISSION_DENIED`, `STALE_REV`, `NOT_FOUND` or `NOT_HOLDING_POSITION`. These are existing codes only.

**Delta (everyone, on success)**

```js
{ version: 1, type: 'efsp-field-state-delta', fieldStateSeq, fieldStates: { updated: [record] } }
```

Affected Strips' `nla` stamps follow on an ordinary `efsp-board-delta`.

**Snapshot**

The snapshot carries `fieldStates: [record]`. There is no resync branch.

**Record**

```js
{ facilityId, rev, activeRunway /* end or null */,
  activeRunwaySource: null | {kind:'WIND', windFromTrue, windKt, missionKey, at} | {kind:'RUNWAY_CHANGE', changeId, at},
  runways: [{ runwayId, ends, endHeadingsTrue, rackIds, status, arrestingGear,
              suspension: null | {kind:'BARRIER_CHANGE'|'RUNWAY_CHANGE', since, by, positionId, note, requestedBy?, changeId?},
              closure: null | {since, by, positionId, reason, requestedBy},
              lastInspection: null | {at, by, positionId, note},
              pendingRequest: null | {requestId, action, requestedBy, requestedPositionId, requestedAt, note} }],
  runwayChange: null | { changeId, state, fromRunwayId, toRunwayId, proposedBy, proposedPositionId, proposedAt, note,
                         acknowledgers, acks: {[pos]: null | {by, positionId, at, selfCoordinated} | {skipped:true, reason:'UNMANNED', at}},
                         selfCoordinated, rejected: null | {by, positionId, at, cause:'REJECTED'|'WITHDRAWN', note},
                         beganAt, beganBy, completedAt, completedBy, pendingInspection: [runwayId] },
  runwayChangeInProgress /* derived */, hotCargoPad: {name, occupied, occupantFdrId}, alertPad: {…},
  transitions: [...], updatedAt, updatedBy }
```
