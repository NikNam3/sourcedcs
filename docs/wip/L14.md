## What the usage guide should say

- **Who imports**: TAC_C2 (Primary at TACTICAL). The **Import ATO…** button appears only while
  TAC_C2 is held. Paste the USMTF text (atobrief's export), or drop / choose a `.txt` file.
- **The preview**: one row per mission line — mission number, callsign, package, vul window (Z),
  agency, IFF M1/M2/M3, missing fields, warnings — and an action per line: *Bind to <flight>* (with
  the key: Mode 3 or callsign), *New flight*, *Update the tasked flight*, *Skip*. Nothing happens
  until **Import N lines**. Enter previews/imports, Esc closes.
- **Binding**: a line binds to a flight already filed when its squawk matches the ATO's Mode 3 (and
  the callsign agrees), or when only the callsign matches. Two possible flights, or a squawk held by
  a flight with a different callsign, are offered but never picked for you.
- **Callsigns**: longer than 7 characters loses vowels from the back (`ENFIELD11` → `ENFLD11`). One
  that still does not fit needs a callsign typed before the line can be imported.
- **Squawks**: a new flight squawks the ATO's Mode 3 if it can be assigned; otherwise crc-sync's own
  code and a warning. A flight that was already filed keeps its ATC code; if the ATO says another,
  every Strip of the flight shows `M3 ATO <code>` until the codes agree.
- **Dates**: the ATO's date is ignored; its times go on the mission's calendar (a note says so).
- **The AR badge**: `AR SHELL71` on a receiver, `AR ×2` on the tanker. Select any of them to
  highlight the others. It is **not MARSA** and declares nothing.
- **Mode 1/2** are read-only: see them in the ▼ view of any Strip of the flight, with the ATO's
  Mode 3, datalink, SCL, mission type, agency and frequencies, on-station time and AR detail.
- **Re-import**: import the amended ATO. Lines already on the Board become *Update*: ATO values are
  replaced, anything a controller typed is kept (the preview says which). Flights the new ATO no
  longer mentions are listed and left alone. Only one ATO is active at a time.
- **ATO first, filed later**: when OPS types the callsign of an ATO flight that has no ATC Strip, the
  toolbar offers "file against ATO mission <msn>"; the DEPARTURE is then the same flight, same code.

## What the briefing should say

- The ATO's values live **on the FDR** through **one setter**, `applyAtoTasking` — never through
  `WRITABLE_PATHS`/`setField` (that would reopen D24 and mark ATO values as controller-typed).
- Traps met: the render signature (`bay-view.js` `_stripSignature`-style `parts`) must include

## Findings for other lanes

- **Bind preselection across callsigns (supervisor).** A pre-filed flight with a *different* callsign
  squawking the ATO's code (the "ATO's squawk is taken" walk) would have been preselected `BIND` by
  the briefing's rule. Changed to "offered, not preselected" with `MODE3_HELD_BY_OTHER`.
- **`bay-view.js` render signature (L15/L16/L23, anyone adding cross-Strip state).** A Strip's
  signature (`parts.push('mhl:' …)` area) decides whether it is rebuilt; state that comes from
  another flight's Strips must be in it. L14 added one line (`ar:`).
- **Duplicate synthetic-code warning (L3, cosmetic).** A 6xxx Mode 3 gets L3's `MODE3_SYNTHETIC` and
  L14's `MODE3_NOT_ADOPTED`; the second states the consequence. Could be merged later.
- **Re-import bumps `rev` on unchanged flights** (the `atoRef` changes). Harmless; noted.
- **Client code allocation (L25/atobrief).** H64 means the ATO's Mode 3 becomes the squawk: atobrief
  handing out colliding codes now yields duplicate warnings on the Board.
- `strip-view.js`'s three wave-2 edits are byte-identical to L1b/L12/L13's; L14's own lines are in
  separate places, so the merge should be clean.
