## Defaults taken (P2) and rulings applied

Rulings from `decisions.md` that override the briefing:

- **H13 / H26** — the hull is **CVN-72, DCS unit `UNION`**, type `CVN_72`, `hullId: 'CVN-72'`.
  It is `DEFAULT_HULL` in `ship-state.js`. This replaces the briefing's CVN-75 / `CVN-1`.
- **H27** — the marshal radial **defaults to final bearing + 180 and is settable by Marshal**. There
  is a new stack op `SetMarshalRadial` and a stored `stack.marshalRadialDeg` (null means the
  default). The briefing's Q3 default was BRC + 180.
- **H28** — there is no automatic compression. Remove leaves a vacancy; `CloseUp` is explicit.
- **H29** — one stack, keyed by `stackId` (`DEFAULT_STACK_ID = 'MAIN'`). The Part B store holds
  `stacks: { [stackId] }` per hull.
- **H30** — no FACSFAC; the APP lanes alternate `[SOURCE-DEFINED]`.
- **H31** — the approach button is a validated integer with no default buttons. The range stays
  **1–20** `[SOURCE-DEFINED]` (briefing Q7).
- **H11** — every time is the injected mission-clock `now`/`at`. `setCase` refuses a missing `at`,
  so no `Date.now()` fallback exists.
- **H15 / S-W3** — every bearing is held in **true**. There are two injected values:
  - `gridConvergenceDeg` converts DCS's grid heading to true;
  - `magneticVariationDeg` feeds `displayBearing` / `marshalMessage` to show magnetic.

  If either is missing, the value is labelled `G` or `T`. A true value is never shown as if it were
  magnetic.
- **H42** — own coalition is injected into `matchHullTrack`. L17 passes the server's
  `CRCSYNC_COALITION` value.
- **Q62 (S-ALL → a)** — L17 derives night from mission time plus sun elevation at the ship. The
  model takes `night` as an input.
- **Q63 (S-ALL → a)** — the carrier flight fields live at **`fdr.military.carrier`**: ADR 0052's one
  namespace, with a sub-object like `military.mtr`.

Choices of my own (`[SOURCE-DEFINED]`, recorded in ADR 0064):

- **An insertion ripple stops at the first vacancy**, and inserting into a vacant slot moves nobody.
  The briefing said "every entry ≥ i". With no gaps the two readings are identical. With a gap, mine
  re-clears fewer pilots, in the spirit of H28.
- **Move up** (to a higher index) is still remove-without-close-up plus insert, as the briefing says.
  The vacancy it leaves stays until `CloseUp`.
- **Push ordinal for lane feeding** is the entry's rank in the stack. Pushed entries still in the
  stack count; gaps do not.
- **`lowStateLb` is its own field, not M17 `military.fuelState`.** The guide's §6.4 defines M17 as
  endurance ("playtime remaining"), a time, not pounds.
- **`applyShipStateInput(inputs, input)` returns `{ ok, inputs }`**, where the briefing had
  `(state) → { shipState }`. The Part B store keeps `shipInputs` separately and rebuilds the banner
  every tick, so the input record is what gets written.
- **Altimeter band** 27.00–32.00 inHg. The approach button refuses any integer ≥ 100 as a frequency.

## For the usage guide and the briefing (supervisor to merge; I did not edit shared docs)

Usage guide, carrier section (once L17 has built the UI):

- The Marshal stack position is the only number you set for a recovering aircraft. Angels, DME and
  push time follow from it and cannot be typed.
- To re-sequence, drag the Strip to a slot. Everyone between moves together.
- Taking an aircraft out leaves a gap. Close it with "Close up" if you want the stack to compress.
- Pushing (Commence) never moves anyone else.
- PriFly sets the Case, and every carrier Strip changes at once. A weather advisory appears only
  when the set Case is less restrictive than the reported weather. It never blocks the change.
- In Case I the stack is a list of squadron altitudes, with no push times.
- Set EEAT, approach button and bingo on the launch Strip. They belong to the flight and appear
  again on the recovery Strip.
- Enter the approach **button** number, not a frequency.
- The ship banner is computed from DCS. Only the altimeter can be overridden.
- Bearings are magnetic. A `T` or `G` suffix means the variation or grid convergence is not known
  yet.

## Found for other lanes / the supervisor (recorded, not fixed)

- **ADR 0042 line 48 names `crc-sync/config/radar-specs.json`.** The file is `sensor-specs.json`
  (`radars.js`). This belongs in the errata ADR 0060 or its successor.
- **`tests/efsp-correlation-reconciler.test.mjs` does not force an eligibility decision for new
  states.** It only checks that the states already listed still exist. The comment at
  `correlation-reconciler.js:50-52` claims "adding one forces the decision", which the test does not
  do. L17 must pin the carrier states (ADR 0064 B5), and a general fix would help every later Role.
- **The client already has a grid-convergence correction** (`crc-desktop/app/public/js/geo.js`,
  per `grpc-client.js:353`). crc-sync has none. L17's ship-state tick needs a server-side
  convergence source for the theater. That fits the per-theater table being built for S-W3, with
  the TM constants in `tools/miztoyaml/projection.py`.
- **`station-coverage.js`'s `{kind:'carrier'}`** matches every ship's search and approach radar
  (trap T13). ADR 0064 B1 proposes the selector extension. This is not a bug today, because no
  carrier Position exists yet.
